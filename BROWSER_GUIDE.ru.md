# Локальный браузер WebCodex

## Подключение личной сессии

Собранное расширение находится в `browser-extension/` (и в ZIP поставки).
Установите его вручную в Chrome/Edge через страницу расширений, режим
разработчика → «Загрузить распакованное расширение». Постоянный ID:
`pmobmihkpbblajdanleplliihfmcdmpp`; manifest содержит только публичный ключ.

Зарегистрируйте Native Messaging host под тем же пользователем, под которым
работают браузер и agent. Администраторские права не нужны:

```powershell
./webcodex-agent.exe --install-browser-host
$env:WEBCODEX_BROWSER_ENABLED='1'
$env:WEBCODEX_BROWSER_PERSONAL_ENABLED='1'
# Затем запустите этот же ./webcodex-agent.exe с обычными Gate URL и токеном.
```

Linux: `./webcodex-agent --install-browser-host`; регистрация создаётся
для Google Chrome, Chromium и Edge в пользовательских NativeMessagingHosts.
Windows: HKCU для Chrome и Edge. Не перемещайте бинарник после регистрации;
после обновления/перемещения повторите установку. `--remove-browser-host`
удаляет регистрацию WebCodex, сохраняя профили и браузер.

### Постоянный доступ — включается один раз

В расширении **WebCodex Local Browser** включите **«Постоянный доступ ко всем
вкладкам сайтов»**. Настройка сохраняется в этом профиле Chrome/Edge.
Расширение само подключается к агенту при запуске браузера, восстанавливает
связь после перезапуска агента и публикует открытые и новые HTTP/HTTPS вкладки.
Для подключения каждой вкладки нажимать кнопку больше не нужно.
Управление конкретной вкладкой подключается только при обращении инструмента;
получение списка вкладок не читает их содержимое и не включает debugger.
Если открыта только внутренняя страница новой вкладки Chrome, при первом
запросе personal создаётся отдельная пустая вкладка в том же личном профиле.
Новый чат может повторно открыть текущую personal-сессию без `profile_in_use`.
Браузер и агент должны работать под одним пользователем.

При переходе с версии 1.0 обновите **и агент, и расширение**: остановите агент,
пересоберите его через `build.bat` (или замените EXE готовой новой сборкой)
и запустите свой BAT заново.
На `chrome://extensions` нажмите «Обновить» у WebCodex Local Browser (версия 1.1.1),
затем включите постоянный доступ. Новый режим не требует изменений Gate или OAuth.

**«Пауза»** сохраняется после перезапуска браузера; продолжить можно локально
кнопкой **«Продолжить»**. **«Отключить всё»** выключает постоянный доступ и
автоподключение. Отключение сессии из чата освобождает управление вкладками,
сохраняя локально разрешённый постоянный доступ для следующей задачи.
Разрешение создавать новые вкладки и popup задаётся отдельным checkbox и
тоже сохраняется. Chrome может показывать уведомление о debugger при обращении к вкладке.

### Только выбранная вкладка

Если постоянный доступ не нужен, выберите **«Только текущая вкладка»**
в авторизованной вкладке. Это выключает постоянный доступ. По умолчанию доступны
HTTP/HTTPS переходы в этой вкладке; можно ограничить их текущим origin.
После обрыва связи в этом режиме вкладку нужно подключить вручную снова.
Для localhost/intranet включите локально `WEBCODEX_BROWSER_ALLOW_LOCAL=1`.
Затем вызовите `browser_open mode=personal` с новым `request_key`.

В личном режиме работают те же инструменты, включая iframe и screenshot;
cookies и storage браузер применяет сам. Пауза из расширения приоритетнее
удалённого resume: продолжение после локальной паузы выполняется локально.
Отключение снимает debugger и сохраняет исходный браузер. Закрывать через
инструменты можно только вкладки, созданные для задачи; личная вкладка
сохраняется. После обрыва bridge текущая MCP-сессия отзывается. При постоянном
доступе расширение автоматически восстанавливает связь в ранее разрешённом
профиле; затем откройте новую personal-сессию. Локальная пауза сохраняется.
DevTools может отозвать debugger-подключение; инструмент вернёт disconnected.

Native Messaging использует framing с длиной сообщения и максимумом 1 MiB.
Windows named pipe допускает только текущего пользователя, исключает удалённых
клиентов и проверяет бинарник отправителя. Linux Unix socket имеет mode 0600,
проверяет UID/PID и путь бинарника. Дополнительно проверяются случайный
bridge token и origin установленного расширения. Публичный локальный порт
не добавляется. Одновременно подключён один personal bridge данного пользователя.

Личные загрузки попадают в `Downloads/WebCodex/<session-id>/<download-id>`.
Если стандартный каталог браузера изменён, задайте локально
`WEBCODEX_BROWSER_DOWNLOAD_DIR`. При сохранении агент проверяет этот точный
путь и destination через allowed roots; перезаписи нет. Ограничение 64 MiB
в Chrome контролируется polling, а окончательное чтение проверяет размер
повторно; для жёсткого дискового лимита нужна квота ОС.

Проверки без личных аккаунтов: `node --test browser-extension/background.test.cjs`,
Go-тесты framing/IPC/отзыва доступа; с `WEBCODEX_BROWSER_TEST=1` IPC-адаптер
использует уже авторизованную вкладку отдельного тестового Chrome.
Установка расширения в обычном профиле, Linux GUI и отображение MCP image
в конкретном клиенте требуют ручной приёмки; автотест их не имитирует.

Есть отдельная проверка **реально установленного personal-расширения**:
`TestInstalledPersonalBrowserLive` в `cmd/gate/personal_live_test.go`.
По умолчанию она пропускается. Для запуска задайте `WEBCODEX_PERSONAL_LIVE_TEST=1`
и `WEBCODEX_PERSONAL_LIVE_AGENT` с абсолютным путём зарегистрированного EXE.
Перед тестом остановите обычный агент; после теста запустите его снова.
Тест использует временный локальный Gate, проверяет personal-сессию, список
разрешённых вкладок и snapshot выбранной страницы без вывода её содержимого.
Требуется уже включённый постоянный доступ в личном профиле браузера.
Для проверки создания вкладки также явно задайте `WEBCODEX_PERSONAL_LIVE_MUTATIONS=1`
и разрешите создание вкладок в расширении. Тест создаёт свою вкладку, открывает
Google, читает страницу и закрывает только созданную им вкладку.

## Управляемый профиль

Включите в окружении локального агента `WEBCODEX_BROWSER_ENABLED=1` и
подключите клиент к `/mcp/v5`. Сначала обновите Gate, затем agent. v3/v4
сохраняют прежние схемы. При выключенной функции браузерные инструменты
не публикуются и прямые вызовы отклоняются. Gate tool policy применяется
к каждому инструменту. Браузер запускается на компьютере агента.

`clean` — отдельный временный профиль, который удаляется при отключении.
`persistent` — отдельный профиль WebCodex: войдите вручную один раз,
авторизация сохраняется при штатном закрытии браузера и перезапуске.
Путь браузера задаёт локальная настройка `WEBCODEX_BROWSER_PATH`;
произвольные executable, флаги или пути профиля из чата не принимаются.
`WEBCODEX_BROWSER_DIR` по умолчанию находится в пользовательском config-dir
в `webcodex/browser/<отпечаток агента>`. Отпечаток из Gate URL и agent token
разделяет профили и журналы разных агентов; сам token не записывается.
Смена этих настроек выбирает новый каталог. Для сохранения конкретного
профиля задайте явный отдельный `WEBCODEX_BROWSER_DIR` этому агенту.
Доступ к каталогу ограничивается текущим пользователем.

Обычный запуск — видимое окно Chrome/Chromium/Edge, без `--no-sandbox`.
Нужна интерактивная GUI-сессия: Windows-служба без рабочего стола и Linux
без DISPLAY/Wayland не дают видимого окна. Запускайте agent в своей
пользовательской сессии; существующая системная service-unit этого не обещает.

Используйте `browser_open` с `mode` и уникальным `request_key`.
В ответе session ID; затем `browser_navigate` (`action=url`, `url`),
`browser_snapshot`, `browser_screenshot`, `browser_interact` и `browser_wait`.
Пароли вводятся вручную: fill парольного поля возвращает `waiting_user`.
MFA, CAPTCHA и consent также проходятся вручную; `browser_control`
позволяет приостановить задачу (`waiting_user`/`pause`) и продолжить (`resume`).
Автоматическое распознавание всех видов CAPTCHA не обещается.

Snapshot включает ограниченный текст, интерактивные элементы, дерево
доступности, frame IDs и open shadow DOM. Закрытые shadow roots недоступны.
Для элемента передавайте `snapshot_id` + `element_id` и тот же `frame_id`;
после навигации старый элемент отклоняется. Можно использовать точный
CSS `selector` либо `role` + `name`; неоднозначные совпадения отклоняются.
Iframe читается и управляется через `frame_id` из snapshot.
Координатные click/drag требуют актуальных `viewport_width/height`.
Диалоги управляются `browser_interact action=dialog accept=true/false`.

Разрешены HTTP/HTTPS, без URL с credentials. `file:`, `chrome:`,
`javascript:` запрещены. Localhost/intranet требуют локального
`WEBCODEX_BROWSER_ALLOW_LOCAL=1`. Навигация, ссылки и сетевые запросы,
включая редиректы, проверяются в коде. Query и fragment удаляются из URL
в результатах/диагностике; headers/body, cookies/storage и пароли не читаются.
Текст страницы — данные, а не инструкции для агента.

Мутации требуют `request_key`. При Retry повторяйте тот же ключ и аргументы;
известный результат возвращается повторно, конфликт аргументов отклоняется.
Резервация сохраняется до действия; после рестарта неизвестный исход даёт
`outcome_unknown` без повторного submit. Журнал ключей хранится на диске 24 часа
без ограничения количества записей: заполнение истории не блокирует новые действия.
В памяти остаётся до 4096 операций; при заполнении кеша самые старые завершённые
результаты автоматически выгружаются. Результаты мутаций доступны с диска по
`request_key` и `operation_id`, поэтому выгрузка не приводит к повторному действию.
Завершённые операции чтения (включая screenshot) имеют отдельный кеш до 128 записей.
Раз в минуту агент удаляет просроченные записи из памяти и с диска, даже без новых
запросов; при запуске также выполняется очистка. Выполняющиеся операции не удаляются;
старые действия после истечения срока не повторять автоматически.
Долгая операция возвращает `operation_id` через одну секунду: читайте
`browser_control action=status operation_id=...`, для отмены — `cancel`.
Операция имеет deadline 30 секунд; browser_wait — до 25 секунд.
Пауза и отключение блокируют новые действия, включая уже стоящие в очереди.

`browser_files action=upload` проверяет путь через WEBCODEX_ALLOWED_ROOTS
и принимает regular file до 64 MiB. Downloads исходно выключены.
Сначала `enable_downloads`, затем клик по ссылке, чтение `downloads` и
`save_download` с download ID и разрешённым destination `path`.
Сохранение никогда не перезаписывает существующий файл; скачанное не запускается.
Скриншоты JPEG уменьшаются до бюджета ответа, это обозначается `truncated`.
`save=true` сохраняет артефакт локально; изображения проходят через Gate к клиенту.

Лимиты: четыре активные сессии, шестнадцать управляемых вкладок/скачиваний,
до 128 вкладок личного профиля (активные и недавно использованные публикуются первыми), 128 выполняющихся
операций, 4096 операций в кеше памяти с автоматической выгрузкой завершённых,
100 диагностических событий, 300 элементов,
200 узлов доступности, не более 64 KiB snapshot при стандартном бюджете.
Диагностика сообщает типы console errors и HTTP failures, исключая аргументы
console, которые могут содержать секреты.
Управляемые промежуточные артефакты ограничены 256 MiB; файлы старше
24 часов очищаются при старте и следующих операциях с артефактами.
Постоянные профили и экспортированные файлы не участвуют в очистке.
Личные downloads остаются в обычном каталоге браузера.

При 128 одновременно выполняющихся операциях дождитесь завершения одной из них:
этот отдельный лимит защищает ресурсы компьютера и не зависит от размера истории.
Для применения новых лимитов и автоочистки обновите и перезапустите локальный агент.

Для проверки установленного браузера:

```powershell
$env:WEBCODEX_BROWSER_TEST='1'
$env:WEBCODEX_BROWSER_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
go test -run TestBrowserManagedEndToEnd -count=1 ./cmd/agent
# Добавьте WEBCODEX_BROWSER_TEST_VISIBLE=1 для проверки видимого окна.
```

Автотест использует локальный сайт и отдельный временный профиль;
живые аккаунты не используются. Откат: выключить браузерную функцию и
подключить `/mcp/v4`; постоянный/личный профиль не удалять.

## Устойчивое заполнение форм и восстановление после ошибки

`browser_snapshot` возвращает `observed_at`, `frame_id`, `document_generation`,
`ready_state`, `counts` и `truncation_reasons`. `ready_state=complete` означает
загрузку документа, но не готовность About, autocomplete или модалки. Ждите
конкретный элемент/текст через `browser_wait`, затем читайте новый snapshot.
`container_selector` у snapshot ограничивает чтение секцией; AX для такого
снимка явно помечается `omitted_for_scope`. Новый snapshot заменяет старые IDs
вкладки, включая снимки других frames.

У native select в `elements` есть `options` с label/value/disabled/selected
и `context` ближайшей группы/fieldset. Для Start Month можно вызвать:

```json
{"browser_session_id":"<session>","tab_id":"<tab>","action":"select","role":"combobox","name":"Month","context":"Start date","value":"October","select_by":"label","request_key":"start-month-unique"}
```

`select_by=auto` (по умолчанию) сначала ищет точный value, затем единственный
точный label; `value` и `label` задают явный режим. Нечётких совпадений нет.
Вместо context можно задать уникальный CSS `container_selector`. Пароли, MFA
и CAPTCHA по-прежнему вводятся пользователем. `fill` поддерживает обычные
поля и contenteditable, включая очистку.

Для `browser_wait` доступны `condition=value` с selector/value, а для
`condition=element` — `state=visible|enabled|absent`. Ошибочный селектор,
неоднозначность и запрет доступа возвращаются сразу, а не маскируются timeout.

Для проверки результата действия у `browser_interact` можно задать:

```json
{"browser_session_id":"<session>","tab_id":"<tab>","action":"click","selector":"button.save","verify_selector":"#saved-project","verify_text":"VectorPlay","verify_timeout_seconds":10,"request_key":"save-project-unique"}
```

`confirmation=action_dispatched` подтверждает отправку UI-действия;
`control_value_verified` — выбранное значение select; `state_verified` —
выполнение заданного условия на текущей странице. Долговременное сохранение
проверяйте отдельным чтением сохранённой записи/страницы. Условие проверки
должно отличать ожидаемый результат от уже существовавшего текста.

Если проверка после клика не прошла, возвращается `state_verification_failed`
с `recovery=verify_outcome` и исходным `verification_error_code`. Клик мог
уже сработать: новый Save/Post/Delete автоматически не выполняйте.
Потерянный ответ восстанавливайте тем же request_key и теми же аргументами;
status и повтор этого ключа не отправляют действие снова. Изменённый snapshot
или аргументы требуют нового ключа только после проверки предыдущего исхода.

Для необязательных media: сохраните подготовленные поля в разрешённом локальном
черновике, сохраните и проверьте основную запись, затем отдельно добавляйте media,
если сайт позволяет такой порядок. После preview 500/timeout получите fresh
snapshot, закройте модалку через доступный Back/Cancel и проверьте поля.
Не перезагружайте несохранённую форму автоматически. Если один повтор поиска
не помог, остановите сценарий и сохраните диагностику. Bridge не исправляет
сервер preview LinkedIn и не создаёт недоступные в UI способы вложения ссылок.

`error.details` содержит operation/session/tab/frame/snapshot IDs и направление
восстановления. `browser_diagnostics` принимает необязательный `operation_id`:
результат связывает ошибки с запросами и операцией при начале запроса. Это
временная корреляция, не доказательство причинности. Возвращаются origin без
путей/query, HTTP status, категория ошибки и длительность при известном старте;
аргументы console, headers/bodies и тексты форм исключены. Последние 100 событий
и до 256 request traces ограничены; `dropped_events` объясняет усечение.

## Несколько личных браузеров и устойчивый псевдоним

В popup расширения задайте псевдоним профиля, например `chrome-linkedin`.
Он сохраняется локально вместе со случайным profile ID установки расширения;
cookies, данные Chrome Profile и имя пользователя ОС для этого не читаются.
Псевдоним задаётся только через popup. Список подключений доступен так:

```json
{"action":"discover"}
```

Это аргументы `browser_control`: в `browsers` перечисляются подключённые
разрешённые профили, их `profile_id`, `connection_id`, alias, product,
состояние паузы и URL/title/window_id/active доступных вкладок. Window ID —
идентификатор API расширения, а не PID/дескриптор окна ОС. Product определяется
по сообщаемому расширением браузерному семейству; он не заменяет проверку
профиля. Список не включает неподключённые окна/профили. Ответ ограничен 64 KiB;
при `truncated=true` часть вкладок опущена, записи самих профилей сохраняются.

Подключение к нужному профилю без смены сайта:

```json
{"mode":"personal","browser_alias":"chrome-linkedin","preferred_browser":"chrome","target_origin":"https://www.linkedin.com","request_key":"attach-linkedin-unique"}
```

Это аргументы `browser_open`. Вместо browser_alias можно передать известный
`profile_id`; `connection_id` относится только к текущему соединению.
`target_origin` выбирает уже разрешённую вкладку и не открывает URL. Если
подходит несколько профилей/вкладок, возвращается `ambiguous_browser` или
`ambiguous_tab`, без перехода в другой контекст. Для нескольких вкладок одного
сайта откройте профиль без target_origin, вызовите `browser_tabs action=list`,
затем `select` с нужным tab_id. URL и целевой аккаунт подтвердите по видимой
странице перед изменениями.

После reconnect profile ID/alias сохраняются, а connection/session/tab IDs
обновляются. Для action=status используйте прежний operation ID; новую вкладку
находите заново. Не повторяйте старую мутацию с новыми IDs без проверки исхода.
Пауза, отзыв scope и disconnect относятся к выбранному подключению. При
нескольких профилях выбор без уточнения запрещён. Коллизии скопированных
profile IDs отклоняются, одинаковые алиасы требуют явного profile_id.

Для этого этапа нужны новый агент и перезагрузка обновлённого расширения в каждом
используемом профиле. Старое расширение остаётся доступно как `identified=false`,
product=unknown: устойчивый алиас до обновления не поддерживается. До восьми IPC
подключений обслуживаются независимо; лимит активных browser sessions остаётся 4.

## Скриншот: metadata и доступность изображения

`browser_screenshot` возвращает JPEG image block в MCP `content` вместе с
metadata: `original_image_width/height`, `image_width/height`, `image_bytes`,
`image_scaled`, `capture_mode=viewport|full_page`, `image_payload_available`.
`truncated=true` означает уменьшение JPEG до бюджета ответа, а не потерю части
страницы; full_page остаётся полным снимком и при масштабировании. Некорректные
нулевые размеры layout отклоняются до capture.

`save=true` добавляет `artifact_path`, а `artifact_available` показывает наличие
локального обычного файла артефакта. При status и image payload сохраняются
исходные байты в пределах кеша операции. Если есть только metadata, выставляется
`image_payload_available=false`: это не подтверждение получения/просмотра картинки
клиентом. Успешное визуальное прочтение нельзя утверждать только по размерам JPEG.

Screenshot — операция чтения: она не пишется в постоянный journal мутаций.
После вытеснения из кеша или рестарта её operation_id может стать неизвестным;
заранее сохранённый artifact_path можно использовать до очистки/TTL. Metadata
или старый путь не гарантируют, что файл всё ещё существует. Рендер конкретным
MCP-клиентом проверяется отдельно от доставки корректного image block через Gate.

## Отмена, очередь и совместимость протокола 2

Для новых гарантий отмены нужны агент из этой поставки и расширение **1.3.0**.
Обновляйте всю папку расширения, включая `command_queue.js`, затем перезагрузите
расширение в каждом используемом профиле. Старые компоненты допускают чтение;
изменение страницы при несовместимом протоколе возвращает
`protocol_upgrade_required` с `recovery=update_extension`.

В сессии агента и подключении расширения допускается одна выполняемая команда
и до восьми ожидающих. При переполнении возвращается `browser_busy` с
`recovery=wait`. Status и отмена проходят вне очереди. Каждая команда расширения
привязана к текущему подключению, версии локального доступа и сроку исполнения
не более 30 секунд. Проверки повторяются после асинхронных подготовительных
шагов, перед отправкой ввода или навигации в Chrome.

`pause`, `waiting_user`, `cancel` и `disconnect` сбрасывают ожидающую работу.
После `resume` отменённые действия не возобновляются. Смена локального доступа
также делает старые команды недействительными; новое подключение не ждёт
очереди отключённого подключения. Локальная пауза имеет приоритет над удалённым
resume, в том числе во время сохранения настроек расширения.

`phase` показывает стадию операции: `reserved`, `queued`, `executing`,
`dispatch_started`, `not_dispatched`, `completed` или `unknown`. В ошибках поле
находится в `error.details`. Оно относится к отправке возможного изменения
страницы, а не к завершению сетевой загрузки или сохранению формы на сайте.
`cancelled_before_dispatch` означает, что изменение ещё не было отправлено
браузеру; `recovery=stop`. После начала отправки отмена или потеря транспорта
может вернуть `outcome_unknown` с `recovery=verify_outcome`.

Отмена не отзывает уже переданный Chrome клик и не откатывает изменения сайта.
Перед повторной мутацией проверьте фактическое состояние. Повтор с тем же
`request_key` получает сохранённый исход операции и не запускает действие снова.
Завершение ожидания RPC-клиента само по себе не отменяет операцию: используйте
`browser_control(action=cancel, operation_id=...)` и затем status.

Управление паузой и отменой остаётся доступным при задержке команды Chrome.
Уже выполняющийся вызов Chrome не прерывается искусственным освобождением
очереди: следующая мутация не запускается параллельно с ним. После сбоя может
потребоваться восстановление подключения; это не подтверждение отсутствия
побочного эффекта. Ускорение snapshot и работа без лишней смены фокуса относятся
к следующим этапам [плана](BROWSER_NEXT_STABILITY_PLAN.ru.md).

## Понятный вывод в консоли агента

Браузерные действия видны и без WEBCODEX_DEBUG: начало, выбранная вкладка,
название страницы и URL, затем результат и длительность. Короткий ID связывает
строки одной операции. Для чтения выводятся число элементов, длина текста,
отметка усечения и первые 240 знаков прочитанного текста. Список вкладок показывает
их названия, адреса и IDs; длинный список помечается как усечённый.

Если RPC вернул running, консоль показывает стадию ожидания, а окончательный
результат появляется самостоятельно после завершения операции. Retry указывает
на сохранённую операцию и не создаёт повторного действия. Ошибки обычного режима
не дублируются общей строкой Gate.

Вводимый текст и значения полей не печатаются. Из URL убираются credentials,
query и fragment; управляющие символы страницы экранируются. Короткая выдержка
может содержать текст открытой страницы. Вывод в консоль не создаёт дополнительных
CDP-запросов: контекст берётся из уже полученных результатов и каталога вкладок.

Для обычного чтения можно передать `browser_snapshot(detail="light")`: текст,
элементы и frames сохраняются, полный AX tree пропускается
(`accessibility_status=omitted_by_request`). По умолчанию остаётся `full`.
В пределах операции каталог кадров переиспользуется; URL проверяется перед JS,
а смена документа во время чтения возвращает frame_changed вместо смешанного
снимка. На warm personal frame стенд показывает 4 IPC-вызова вместо 10 для full
и 3 для light. Это число вызовов, а не обещание ускорения сайта в процентах.

Расширение 1.3.1 объединяет повторные обновления каталога вкладок. Пауза и отзыв
доступа действуют сразу. Закрытие managed Chrome ограничено по времени; если оно
задержалось, агент сообщает об этом и приостанавливает новые изменения до конца
очистки. Принудительное завершение относится только к Chrome, запущенному агентом.

`browser_control(action="discover")` также показывает `health` и `health_reason`.
При `journal_corrupt` файловые инструменты и команды продолжают работать,
а изменения браузера получают `browser_unhealthy` до записи новой операции.
Повреждённая запись сохраняется и после перезапуска продолжает блокировать
мутации. Возобновление требует восстановления защиты от повторов, проверки
неопределённых изменений на сайте и перезапуска агента. Автоматического удаления
или игнорирования повреждённого журнала нет.

Кеш завершённых browser operations ограничен также 32 MiB сериализованных
payload (включая изображения и временные детали ошибок). Сначала вытесняются
старые чтения; retry index и записи мутаций на диске сохраняются до своего TTL.
Это бюджет кешируемых данных, а не лимит общего RSS процесса.

## Подключиться к конкретной уже открытой вкладке

В расширении 1.4.0 добавлены проверка цели и сообщение версии/capabilities в
`browser_control(action="discover")`. Для работы в существующем аккаунте:

```json
{"mode":"personal","reuse_only":true,"exact_url":"https://example.com/account","browser_alias":"work","window_id":12,"request_key":"attach-existing-unique"}
```

Это аргументы `browser_open`. `window_id` необязателен и относится к каталогу
расширения, не к HWND Windows. Между разными профилями неоднозначность приводит
к ошибке. Несколько совпадений внутри выбранного профиля выбираются по active,
затем window ID и tab ID; ответ содержит matching_tabs и selection_reason.
Новая вкладка, профиль и навигация в этом режиме не создаются.

Ответ `binding_verified=true, readable=true` появляется после проверки фактических
URL/окна и чтения DOM. Возвращаются title и короткая выдержка текста. Это не
доказательство входа в нужный аккаунт: `auth_state=unverified`, проверьте страницу.
Обычный `ready` без этих признаков означает только открытие сессии.

Сохраните `binding_revision` и передавайте его во все следующие операции с
`browser_session_id`. Тогда смена выбранной вкладки не переключит задачу, а смена
URL/окна/локального доступа остановит её с binding_changed/rebind_target.
Строгая сессия отклоняет вызовы без binding_revision. Для другого URL выполните
новое явное подключение reuse_only; автоматического fallback на persistent нет.
Параметры signed URL используются только в разрешённом транспорте и убираются
из выдаваемых URL и консольного контекста.

Для `browser_interact(action="fill")` доступен `input_mode="native"`: Unicode
через Input.insertText, read-back и undo. По умолчанию остаётся compatibility;
автоматического повтора другим способом при ошибке нет. Пароли вводятся вручную.
Для personal native-ввода требуется расширение с capability native_text_v1.

Клик и выбор вкладки по умолчанию используют focus_policy=preserve: отсутствует
Page.bringToFront, видимый элемент не прокручивается заново. Для явного вывода
вкладки на передний план задайте focus_policy=activate. Это политика вызовов
браузера, а не гарантия отсутствия любых изменений фокуса в ОС или самом сайте.

Резерв и итог browser mutation записываются ограниченным writer вне общей
блокировки менеджера. Статус/отмена доступны при медленной записи; до успешного
сохранения резерва действие не отправляется. При восьми занятых слотах новая
мутация получает browser_busy до принятия ключа. Закрытие writer ограничено
по времени; неизвестный исход не разрешает автоматическое повторение.

## Чтение записей и виртуализированных списков

Для записей с устойчивыми DOM IDs используйте browser_snapshot:

```json
{"browser_session_id":"...","binding_revision":"...","container_selector":"#messages","record_selector":"article.message","id_attribute":"data-message-id","text_selector":".content","author_selector":".author","time_selector":"time","attachment_selector":"a.attachment","page_size":25}
```

Возвращаются records с ID, текстом, автором, временем и вложениями именно этой
записи. У вложений id_source=ordinal означает лишь позицию внутри сообщения,
а не устойчивый ID. URL вложений очищаются от параметров доступа; это каталог,
не вечные ссылки для скачивания. text_truncated/attachments_truncated и общие
truncation_reasons показывают ограничения.

Для следующей страницы передайте next_page_token с прежними селекторами.
После изменения DOM или замены контейнера получите stale_generation: начните
чтение заново и объединяйте данные по устойчивым IDs. До 2 000 текущих DOM-записей
проверяются за проход; на этом пределе курсор заканчивается с record_limit.
Лимит ответа уменьшает страницу, сохраняя корректную следующую позицию.

Прокрутка нужного списка:

```json
{"browser_session_id":"...","binding_revision":"...","action":"scroll","container_selector":"#messages","record_selector":"article.message","id_attribute":"data-message-id","y":600,"request_key":"scroll-messages-unique"}
```

Операция возвращает first_id/last_id, visible_count, new_ids, scroll_moved и
dom_changed. При record_selector она ждёт смены IDs до двух секунд.
at_scroll_end — только геометрический край контейнера. collection_complete и
history_end_verified остаются false: ни край прокрутки, ни конец страницы DOM
не доказывают полноту удалённой истории.

`browser_files(action="save_download")` сохраняет фактические байты штатной
загрузки и возвращает SHA-256, MIME и размеры распознанного изображения.
verified=true относится к сохранённым байтам, source_original_verified=false
не даёт выдавать PNG определённого размера за подтверждённый оригинал.
Повтор с теми же байтами возвращает duplicate=true, другой файл не перезаписывается.
Запуск скачивания по произвольной ссылке и обход системных диалогов этой операцией
не добавлены; используйте разрешённую штатную загрузку страницы.

Диагностика читает накопленные события без очереди страницы и без CDP, в том
числе во время долгого wait. URL/DNS-проверки расширения выполняет ограниченный
пул: медленный DNS не задерживает reader, ответы команд и отмену. При переполнении
проверка не разрешает запрос автоматически; срабатывает ограниченный timeout.
