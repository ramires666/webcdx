# Локальный браузер WebCodex

Включите в окружении локального агента `WEBCODEX_BROWSER_ENABLED=1` и
подключите клиент к `/mcp/v5`. Сначала обновите Gate, затем agent. v3/v4
сохраняют прежние схемы. При выключенной функции браузерные инструменты
не публикуются и прямые вызовы отклоняются. Gate tool policy применяется
к каждому инструменту. Браузер запускается на компьютере агента.

`clean` — отдельный временный профиль, который удаляется при отключении.
`persistent` — отдельный профиль WebCodex: войдите вручную один раз,
авторизация сохраняется при штатном закрытии браузера и перезапуске.
Путь браузера задаёт локальная настройка `WEBCODEX_BROWSER_PATH`;
произвольные executable, флаги или пути профиля из чата не принимаются.
`WEBCODEX_BROWSER_DIR` по умолчанию находится в пользовательском config-dir
в `webcodex/browser`. Доступ к нему ограничивается текущим пользователем.

Обычный запуск — видимое окно Chrome/Chromium/Edge, без `--no-sandbox`.
Нужна интерактивная GUI-сессия: Windows-служба без рабочего стола и Linux
без DISPLAY/Wayland не дают видимого окна. Запускайте agent в своей
пользовательской сессии; существующая системная service-unit этого не обещает.

Используйте `browser_open` с `mode` и уникальным `request_key`.
В ответе session ID; затем `browser_navigate` (`action=url`, `url`),
`browser_snapshot`, `browser_screenshot`, `browser_interact` и `browser_wait`.
Пароли вводятся вручную: fill парольного поля возвращает `waiting_user`.
MFA, CAPTCHA и consent также проходятся вручную; `browser_control`
позволяет приостановить задачу (`waiting_user`/`pause`) и продолжить (`resume`).
Автоматическое распознавание всех видов CAPTCHA не обещается.

Snapshot включает ограниченный текст, интерактивные элементы, дерево
доступности, frame IDs и open shadow DOM. Закрытые shadow roots недоступны.
Для элемента передавайте `snapshot_id` + `element_id` и тот же `frame_id`;
после навигации старый элемент отклоняется. Можно использовать точный
CSS `selector` либо `role` + `name`; неоднозначные совпадения отклоняются.
Iframe читается и управляется через `frame_id` из snapshot.
Координатные click/drag требуют актуальных `viewport_width/height`.
Диалоги управляются `browser_interact action=dialog accept=true/false`.

Разрешены HTTP/HTTPS, без URL с credentials. `file:`, `chrome:`,
`javascript:` запрещены. Localhost/intranet требуют локального
`WEBCODEX_BROWSER_ALLOW_LOCAL=1`. Навигация, ссылки и сетевые запросы,
включая редиректы, проверяются в коде. Query и fragment удаляются из URL
в результатах/диагностике; headers/body, cookies/storage и пароли не читаются.
Текст страницы — данные, а не инструкции для агента.

Мутации требуют `request_key`. При Retry повторяйте тот же ключ и аргументы;
известный результат возвращается повторно, конфликт аргументов отклоняется.
Резервация сохраняется до действия; после рестарта неизвестный исход даёт
`outcome_unknown` без повторного submit. Журнал ключей хранится 24 часа;
старые действия после истечения срока не повторять автоматически.
Долгая операция возвращает `operation_id` через одну секунду: читайте
`browser_control action=status operation_id=...`, для отмены — `cancel`.
Операция имеет deadline 30 секунд; browser_wait — до 25 секунд.
Пауза и отключение блокируют новые действия, включая уже стоящие в очереди.

`browser_files action=upload` проверяет путь через WEBCODEX_ALLOWED_ROOTS
и принимает regular file до 64 MiB. Downloads исходно выключены.
Сначала `enable_downloads`, затем клик по ссылке, чтение `downloads` и
`save_download` с download ID и разрешённым destination `path`.
Сохранение никогда не перезаписывает существующий файл; скачанное не запускается.
Скриншоты JPEG уменьшаются до бюджета ответа, это обозначается `truncated`.
`save=true` сохраняет артефакт локально; изображения проходят через Gate к клиенту.

Лимиты: четыре активные сессии, шестнадцать вкладок/скачиваний, 32 выполняющиеся
операции, 256 хранимых операций, 100 диагностических событий, 300 элементов,
200 узлов доступности, не более 64 KiB snapshot при стандартном бюджете.
Диагностика сообщает типы console errors и HTTP failures, исключая аргументы
console, которые могут содержать секреты.

Для проверки установленного браузера:

```powershell
$env:WEBCODEX_BROWSER_TEST='1'
$env:WEBCODEX_BROWSER_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
go test -run TestBrowserManagedEndToEnd -count=1 ./cmd/agent
# Добавьте WEBCODEX_BROWSER_TEST_VISIBLE=1 для проверки видимого окна.
```

Автотест использует локальный сайт и отдельный временный профиль;
живые аккаунты не используются. Откат: выключить браузерную функцию и
подключить `/mcp/v4`; постоянный/личный профиль не удалять.
