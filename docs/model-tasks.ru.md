# Параллельные задачи OpenCode в WebCDX

Основная модель передаёт группу задач одним вызовом. Для каждой задачи агент
запускает отдельный процесс OpenCode. Текстовые задачи получают запрос и
результаты зависимостей. Задачи с файлами получают снимки выбранных файлов из
Git, готовят правки в отдельном worktree и возвращают патч для проверки.

## Настройка агента

На Windows `start-local-agent.cmd` ищет OpenCode 2 в стандартной папке npm текущего
пользователя. Затем он вызывает `opencode debug paths db`, чтобы определить путь к
существующей базе OpenCode, если источник авторизации ещё не задан. Для субагентов
в базе нужно активное подключение OpenCode Go. Если OpenCode установлен в другом
месте, перед запуском укажите `WEBCODEX_OPENCODE_PATH`. При запуске EXE напрямую
задайте также один источник авторизации из таблицы.

| Настройка | Значение |
| --- | --- |
| `WEBCODEX_OPENCODE_PATH` | Абсолютный путь к локальному исполняемому файлу OpenCode 2.3.2 или новее. В Windows укажите путь к `opencode.exe` из настроенного `openmcp` или собственной установки. Пустое значение отключает инструменты задач. |
| `WEBCODEX_TASK_KEY_FILE` | Абсолютный путь к локальному файлу, содержащему только ключ OpenCode Go одной строкой. Ограничьте доступ к файлу средствами ОС. Не добавляйте его в Git и не передавайте ключ через чат. |
| `WEBCODEX_TASK_OPENMCP_ENV` | Абсолютный путь к существующему `.env` проекта `openmcp`, например `W:\_python\openmcp\.env`. Агент берёт только `OPENCODE_API_KEY`. |
| `WEBCODEX_TASK_OPENCODE_AUTH` | Абсолютный путь к `auth.json` авторизованного OpenCode. Агент берёт API-ключ только из записи `opencode-go`. |
| `WEBCODEX_TASK_OPENCODE_DB` | Абсолютный путь к базе OpenCode 2 с активным подключением OpenCode Go. Команда `opencode debug paths db` выводит её путь. OpenCode использует выбранное подключение и хранит тестовые сеансы как архивные. Укажите один из четырёх источников авторизации. |
| `WEBCODEX_TASK_MODEL` | Необязательная переменная совместимости. Если она задана, её значение должно быть `opencode-go/hy4-flash-free`. |
| `WEBCODEX_TASK_PARALLEL` | Число одновременно работающих процессов от 1 до 32. По умолчанию 4. |
| `WEBCODEX_TASK_GIT_PATH` | Абсолютный путь к Git. Для Windows укажите `git.exe`. Нужен для задач с файлами. |
| `WEBCODEX_TASK_REPOS` | Разрешённые абсолютные пути к корням Git-репозиториев. Разделитель в Windows — точка с запятой, в Linux — двоеточие. Пути должны входить и в разрешённые корни агента. Пустой список оставляет текстовый режим. |
| `WEBCODEX_TASKS_GATE` | Значение `1` дополнительно открывает эти инструменты в MCP v5 через Gate. Настройте разрешения на инструменты для нужного подключения и агента. Локальный режим работает без этой настройки. |

Профили `build`, `general` и `explore` запускаются на `opencode-go/hy4-flash-free`
с вариантом `high`. Для задач с полем `files` по умолчанию выбирается `build`,
для остальных задач используется `general`. Можно указать профиль явно через
поле `agent` отдельной задачи.

Локальный агент запускает OpenCode по указанному пути. Он предоставляет каждому
процессу отдельную рабочую папку и конфигурацию и передаёт ключ только дочернему
процессу. Доступность модели и расход квоты определяет провайдер. Не передавайте
секреты в заданиях. Текст отправляется провайдеру, а транспортный журнал может
содержать аргументы вызова.

## Как вызвать задачи

Откройте новый сеанс после перезапуска агента. В расширении разрешите инструменты
задач. Через Gate используйте существующий endpoint MCP v5 и обычный выбор
компьютера. `list_agents` возвращает компьютеры.

1. `task_capabilities` показывает модель, лимит очереди и параллельность.
2. `start_tasks` принимает `tasks` с уникальным `key` и текстом `prompt` у каждой
   задачи. При необходимости укажите `agent` и `timeout_seconds` от 10 до 1800 секунд
   на исполнение. Значение по умолчанию равно 180 секундам. MCP клиент передаёт
   устойчивый `request_key` и повторяет тот же ключ с теми же задачами после
   потери ответа. Расширение создаёт ключ автоматически.
3. `get_tasks` принимает полученный `batch_id` и возвращает статусы без полного
   текста. `task_result` принимает `batch_id` и `key` и возвращает результат
   конкретной задачи.
4. `cancel_tasks` принимает `batch_id` и запрашивает отмену всей группы.
   Проверяйте итог командой `get_tasks`. Закрытие чата или разрыв связи не
   отменяет уже принятую группу.

Для длительных задач сохраните `revision` из `get_tasks` и передайте его в
`wait_tasks` вместе с `batch_id`. Агент вернёт новое состояние при изменении
или через пять секунд. `timeout_ms` задаёт меньшую задержку. Пустая ревизия
возвращает текущее состояние сразу. Для восстановления ID используйте
`list_tasks` с `limit` от 1 до 25. `next_cursor` из ответа можно передать как
`cursor`, чтобы получить следующую страницу своих групп.

Расширение показывает последнюю группу текущего сеанса и количество задач по
статусам. Кнопка «Обновить статусы» делает отдельный запрос к исходному агенту,
когда разрешён инструмент `get_tasks`. Запрос не отправляет сообщение модели.

## Зависимости и работа с файлами

В `depends_on` перечислите ключи задач той же группы. Задача ждёт их
завершения и получает до 16 КиБ их текстовых результатов. Если предшественник
завершился ошибкой или отменён, зависимая задача получает статус `blocked`.
Патчи зависимостей не меняют исходный снимок. Если задаче нужна версия проекта
с уже внесёнными правками, начните новую группу с нового коммита.

Для работы с кодом передайте в `start_tasks` абсолютный `project_root`. В
`files` каждой задачи укажите точные относительные пути для правок. В
`context_files` можно передать отдельные файлы для чтения. На одну задачу
допускается до 16 путей и до 48 КиБ исходного UTF-8 текста. Пути используют
`/`. Две задачи одной группы не могут менять один файл.

```json
{
  "request_key": "docs-and-test-1",
  "project_root": "W:\\_python\\webcdx",
  "tasks": [
    {
      "key": "docs",
      "agent": "build",
      "prompt": "Объясни назначение очереди коротким абзацем.",
      "files": ["docs/model-tasks.ru.md"]
    },
    {
      "key": "example",
      "prompt": "Добавь короткий пример сценария с двумя задачами.",
      "files": ["docs/task-example.md"],
      "depends_on": ["docs"]
    }
  ]
}
```

Агент фиксирует текущий коммит `HEAD` при первом принятии группы и берёт снимки
из него. Незакоммиченные правки остаются в основном checkout. OpenCode получает
снимки только перечисленных файлов и возвращает новые версии как структурированный
текст. Агент проверяет пути и создаёт, обновляет или удаляет файлы в worktree.
Запуск сгенерированного кода и тестов выполняется отдельным шагом после ревью.

`task_result` возвращает `patch` с путями, базовым коммитом и SHA-256.
`task_patch` читает патч по `batch_id` и `key`. Для следующего фрагмента передайте
`next_offset` из предыдущего ответа как `offset`. Поле `complete` отмечает
последний фрагмент. `max_bytes` задаёт размер фрагмента.

После ревью вызовите `task_integrate` с `batch_id` и массивом
`patches`, где у каждой записи есть `key` и точный `sha256` из `task_result`.
Агент объединяет выбранные патчи в отдельном worktree, проверяет список
изменённых файлов и возвращает `integration_id`. С этим ID `task_patch`
читает общий патч. Основной checkout сохраняет свои изменения. Применение
проверенного патча к рабочей ветке выполняет интегратор.

Одна группа может содержать 100 задач, а вся очередь одного процесса агента
вмещает до 500 ожидающих и работающих задач. Максимум — 16 КиБ текста на
задачу, 256 КиБ на группу и 16 КиБ на результат. Для обрезанного результата
возвращается поле `truncated`.

Завершённые результаты сохраняются в служебной папке агента. При аварийном
перезапуске ожидавшая задача получает статус `interrupted`. Для активной
задачи с неизвестным итогом возвращается `outcome_unknown`. Агент не повторяет
их автоматически. Доступ к группе привязан к исходному подключению Gate или установленному экземпляру расширения. Используйте
один экземпляр агента с включённой очередью на профиль пользователя.

## Проверка субагентов

Из корня исходников в Windows PowerShell выполните:

```powershell
./tools/test-subagents.ps1
```

Команда собирает временный локальный агент и управляемый тестовый процесс
вместо OpenCode. Проверяет параллельные задачи, зависимости, историю, отмену
и объединение патчей через локальный API AIX. Достаточно Go, Node.js и Git в
PATH. Скрипт использует отдельные каталог профиля и Git-репозиторий и удаляет
их после проверки. Этот же сценарий запускается в Windows CI.

Для живой проверки задайте `WEBCODEX_OPENCODE_PATH` и один из источников
авторизации из таблицы выше.

```powershell
./tools/test-subagents.ps1 -Live
```

`-Live` запускает настоящий OpenCode и проверяет отдельный короткий ответ
каждого из трёх профилей на `opencode-go/hy4-flash-free` с вариантом `high`.
На ответ каждого профиля отводится до 45 секунд. Для обоих прогонов скрипт сам собирает
тестовый EXE, заменять и перезапускать установленный агент, расширение и Gate
для запуска тестов не требуется.

## Обновление

Для запуска из исходников используйте `./build.ps1` в корне `webcdx`. Скрипт
компилирует локальный агент и упаковывает расширение в `bin/aix`. Для готового
комплекта используйте собранный `bin/aix/webcodex-agent.exe` и перезапустите
агент. Для локального маршрута замените и перезапустите агент, обновите расширение
до версии 0.5.9 и откройте новый сеанс. Для MCP замените и перезапустите агент
с поддержкой Gate и сервер Gate. В готовом комплекте для MCP оба EXE уже
скомпилированы в `bin/task-mcp`. Локальный комплект работает при остановленном Gate.
