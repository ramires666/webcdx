# Координатор и устойчивое состояние

## Владельцы фактов

Агент сообщает статус и результат исполнения. Gate хранит принятие и доставку
запроса агенту. Расширение хранит выбор инструментов, привязку диалога,
намерение отправки и подтверждение доставки результата в чат.
Адаптер передаёт наблюдения страницы и ревизию источника ответа.
Панель отображает состояние координатора и передаёт изменения отдельных полей.

## Переходы

Чистая функция `WebCodexSession.transition` получает состояние и событие,
возвращает новое состояние и намерения внешних действий. Очередь `enqueue`
применяет результат. Единственный исполнитель использует сохранённое намерение.
Наблюдательное сравнение переходов с прежними фазами выполнено в стенде
до включения функции в рабочий путь. Стенды полного жизненного цикла проверяют
допуски, отправки и число операций после переключения.

| Событие | Состояние и намерение |
| --- | --- |
| call_received | Проверенный вызов ожидает исполнения либо одобрения |
| dispatch_intent | Ключ, аргументы, поколение координатора и разрешения сохраняются вместе |
| operation_status | Полученный статус и идентичность операции, конфликт идентичности блокирует продолжение |
| result_ready | Результат готов, при пользовательской паузе остаётся сохранённым |
| delivery_intent | Сохранено намерение доставки определённой операции в определённый сеанс |
| delivery_confirmed | Подтверждённая операция очищает только собственные поля ожидания |
| pause | Сохраняется предыдущая фаза, новые действия блокируются |
| resume | Проверяется возможность продолжения, согласие и неизвестный исход |
| stop | Сеанс остановлен, известные факты операции сохранены |

У исполнения и доставки есть отдельные `executionStatus` и `deliveryStatus`.
Публичная `phase` сохраняет совместимость панели. Коды причины используются
для восстановления. Старые сохранённые сообщения сопоставляются кодам при
миграции и на совместимом входе прежнего content-скрипта.

## Сохранение и прерывание

Авторитетный снимок `webcodexDurableState` хранится в `storage.local`.
Версия схемы, состояние и намерение передаются одним вызовом записи одного ключа.
Кэш в `storage.session` может содержать снимок либо указатель. Восстановление
сначала читает устойчивый снимок. Старые обычные и большие снимки мигрируются.
Неизвестная версия сохраняется для открытия совместимым кодом.

Каждый экземпляр координатора имеет отдельный идентификатор. Намерение содержит
сеанс, ключ операции, ревизию ответа и редакцию разрешений. Перед отправкой
после ожиданий проверяется актуальность действия.

Пауза, отзыв согласия и смена диалога немедленно меняют локальную редакцию
разрешения новых действий. Запрос прерывания записывается отдельным последовательным
журналом до сигнала отмены UI. Основная очередь затем применяет его к снимку.
После перезапуска неприменённая запись снова блокирует продолжение.
Отзыв автоматического одобрения и выключение автоматической доставки имеют
отдельные редакции. Принятая агентом операция сохраняет возможность опроса.

Проверены потеря session-кэша, отказ записи до отправки, пауза во время записи,
получение результата после паузы, отзыв автоматического одобрения и восстановление
отзыва согласия до обработки очередью. Проверка перезапуска установленного
расширения в настоящем браузере входит в итоговую живую приёмку.

## Предпочтения

Новая панель передаёт имя изменённого поля. Координатор объединяет его
с последними сохранёнными значениями. Запись получает новую ревизию.
Панель сохраняет пользовательский ввод при опросах и отбрасывает более старые
снимки предпочтений. Совместимый полный запрос старой панели поддерживается.
