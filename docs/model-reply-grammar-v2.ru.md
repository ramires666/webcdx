# Грамматика ответа Helper v2

Этап 2 фиксирует контракт для последующей реализации извлечения и разбора.
Примеры всего каталога содержат исходник и точный внутренний вызов.
[Примеры](../ai-studio-extension/test-fixtures/reply-v2-examples.json).

## Рамка

Служебный участок занимает один отдельный источник кода. Открывающая строка
имеет форму `HELPER_<marker> <tool>`, заключительная строка `END_<marker>`.
Маркер состоит из 32 шестнадцатеричных ASCII-символов. В примерах используется
постоянное тестовое значение. Реальный маркер генерируется расширением.
Имена инструментов и полей берутся из полученной схемы.

Перед служебным участком и после него допускается пояснение в отдельных абзацах.
При отображении Markdown рамка помещается внутрь одного блока кода. При наличии
обратных кавычек в теле внешняя ограда должна быть длиннее любой такой серии
внутри тела. DOM-адаптер передаёт границу исходного участка отдельно от пояснения.

Начальная строка и параметры могут иметь внешние горизонтальные пробелы.
Имена инструментов, полей и маркер сохраняют регистр. Разделитель поля — первое
двоеточие. После него один ASCII-пробел относится к оформлению. Остальная часть
строкового значения сохраняется, включая пробелы и двоеточия. Строка без значения
означает пустую строку только для строкового поля.

Пустые строки между параметрами допустимы. Повторное поле, второй независимый
служебный участок, неизвестное поле или конфликт источников вызывают локальную
ошибку. Отсутствующее значение сохраняется неполным. Маркер другого сеанса
образует отдельный конфликт. Для ответа без рамки применяется совместимый v1.

## Типы параметров

Тип значения определяется схемой. Строковый параметр содержит буквальную строку
без JSON-экранирования. Boolean принимает `true` и `false`, регистр допускает
локальную нормализацию. Integer использует целую десятичную запись, number
обычную конечную JSON-запись числа. Для nullable-строки строковое значение
задаётся через структурированный участок, чтобы различать строку `null` и null.

Массив или объект начинается как `field: <JSON>` на одной строке.
Вместо двоеточия допускается знак равенства с записью применённого правила
локального восстановления. Изменение затрагивает разделитель параметра.
Большой вложенный объект можно передать единым параметром `arguments: <JSON>`.
В этом варианте остальные аргументы заголовка запрещены. Разрешено сочетать
`arguments` и сырое тело, если тело не дублирует уже указанное поле.
Структурированный участок проходит общую проверку схемы и ограниченное локальное
восстановление v1. Команды argv, env и массив edits сохраняют свои типы и порядок.

## Сырое тело

| Инструмент | Поле тела |
| --- | --- |
| write_file | content |
| exec_command | command |

Первая самостоятельная строка `---` завершает заголовок. Всё после её перевода
строки до внешней заключительной строки является сырым телом. Ровно один перевод
строки непосредственно перед заключительной рамкой служит разделителем.
Сохраняются LF, CRLF, пустое тело, завершающие переводы строки, пробелы, кавычки,
обратные слеши и вложенные примеры. Тело не участвует в поиске команд и JSON.
Текст заключительной рамки внутри тела сохраняется данными. Закрывает рамку
только последняя строка на подтверждённой внешней границе источника.

У инструментов без тела строка `---` отсутствует. Если она появилась для
инструмента без установленного поля тела, результат сохраняется как ошибка.
exec_command с argv использует заголовок без сырого тела. Одновременное наличие
argv и command отклоняется схемой. Пустой файл задаётся пустым телом.

## Единый внутренний контракт

Разбор возвращает имеющиеся `name` и `arguments`, информацию об источнике
и список применённых локальных правил. Внутренние turn, request_key, agent_id,
operation_id и хеши транспорта создаёт расширение. Проверка схемы и разрешений
остаётся общей для v1 и v2. Инструкция модели показывает один рекомендуемый
шаблон на инструмент. Переход на v2 выполняется после готовности этапов 3–5.

Для участка без сырого тела пропущенный END допускается восстановить на
подтверждённой границе исходника кода после успешной проверки полной схемы.
Участок с телом требует явного завершения. Работа JSON-восстановления ограничена
256 КиБ метаданных. Большое сырое тело проходит отдельно без такого ограничения.
Допустимая глубина аргументов составляет 64 уровня.
