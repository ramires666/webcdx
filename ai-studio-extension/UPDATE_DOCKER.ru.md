# Обновление AI Studio Bridge на Docker Gate

Инструкция для уже установленного сервера в `~/GROM/webcdx` с Compose-сервисом
`gate`, контейнером `webcodex-gate` и данными в `/data`. Команды выполняйте на
сервере по очереди и из указанной папки: так Compose использует прежний проект и
его volume. Если команда завершилась ошибкой, дальше не продолжайте.

Это обновление Gate до `1.5.0-ai-studio-alpha.4`: оно добавляет форму входа для
окна авторизации Chrome. Уже установленные агент alpha.1 и расширение 0.1.1
не требуют замены или перезапуска. После обновления Gate повторите подключение
в панели и введите логин/пароль администратора на странице Gate.

## Gate на сервере

Gate alpha.3 исправляет отказ `login form expired or invalid` при отправке формы
входа из Chrome: политика страницы сохраняет Origin для проверки CSRF.
После обновления закройте старое окно входа и начните подключение заново.
Агент alpha.1 и расширение 0.1.2 для этой правки заменять или перезапускать не нужно.

```bash
cd ~/GROM/webcdx
git pull --ff-only
docker compose build gate
```

`cd` переходит в существующую папку установки. `git pull --ff-only` получает
изменения из текущей Git-ветки и запрещает создавать merge-коммит при
расхождении веток. `docker compose build gate` собирает образ сервиса `gate`,
пока старый контейнер ещё работает; команда не заменяет и не останавливает его.

Остановите Gate, затем скопируйте весь `/data` и `.env`. Это нужно, чтобы SQLite
не менялась во время копирования. На время этого шага Gate будет недоступен:

```bash
docker compose stop gate
mkdir -p backups
backup="$(mktemp -d backups/gate-XXXXXXXX)"
chmod 700 "$backup"
docker cp webcodex-gate:/data "$backup/data"
cp .env "$backup/.env"
```

`docker compose stop gate` штатно останавливает существующий сервис `gate`.
`mkdir -p backups` создаёт папку копий, если её нет. `mktemp -d` создаёт новую
уникальную папку по шаблону `backups/gate-XXXXXXXX`: символы `X` заменяются
случайными символами. `backup` сохраняет полученный путь, а `$backup` использует
его в следующих командах. `chmod 700` разрешает доступ только владельцу папки.
`docker cp` копирует весь каталог `/data` остановленного контейнера
`webcodex-gate` в подпапку `data` резервной копии; `cp` сохраняет файл настроек
`.env` в той же копии под именем `.env`. Не выводите содержимое `.env` в терминал и
не публикуйте резервную копию. Если любая команда копирования завершилась
ошибкой, не заменяйте Gate; выполните
`docker compose start gate` — эта команда запускает существующий контейнер.

Только после успешного завершения обеих копий обновите Gate:

```bash
docker compose up -d --no-deps gate
docker compose logs --tail=30 gate
docker compose ps gate
```

`up -d --no-deps gate`
запускает обновлённый `gate` в фоне (`-d`) без запуска зависимостей
(`--no-deps`), сохраняя прежний volume. `logs --tail=30 gate` показывает
последние 30 строк журнала, а `ps gate` — состояние сервиса. Убедитесь, что Gate
запустился с версией `1.5.0-ai-studio-alpha.4`, а после соединения видна версия агента.
Версии должны сообщаться фактически при соединении; для старого агента без
поддержки версии Gate пишет «версия не передана».

Не выполняйте `docker compose down -v`: эта команда удалит volume с данными.
Gate обновляется и перезапускается; расширение Chrome версии 0.1.1 уже актуально,
его заменять не нужно — перезагрузите вкладку AI Studio. Windows-агент обновите и
перезапустите, если он ещё не версии `1.5.0-ai-studio-alpha.1`: готовый EXE находится в
`C:/projects/webcdx/bin/ai-studio-bridge/webcodex-agent.exe`. Он уже собран,
самостоятельная сборка не нужна. Хостовые `go` и `build.sh` для Docker не нужны:
образ Gate собирается Docker из исходников.

Это инструкция по процедуре; обновление на реальном сервере здесь не выполнялось.
