# WebCodex AI Studio Bridge — alpha 0.1.5

Расширение связывает AI Studio Playground в браузере с WebCodex Gate и выбранным агентом. Это alpha: селекторы страницы AI Studio не проверялись в живом браузере, поэтому интерфейс может измениться.

## Что потребуется

- Chrome 125 или новее, запущенный WebCodex Gate с настроенным bridge OAuth.
- Адрес Gate и OAuth Client ID, показанный в карточке MCP Gate.
- Агент должен быть зарегистрирован и разрешён для MCP-клиента. Это разрешение выбирает доступный компьютер; инструменты дополнительно ограничиваются Gate bridge и выбором в панели.

Расширение не обращается к API модели и не требует ключей AI Studio. Модель используется через обычную открытую страницу AI Studio Playground. Авторизация в Gate проходит отдельно по OAuth Authorization Code с PKCE. В расширение вводится OAuth Client ID Gate; Client Secret и административные секреты сюда не вводить.

## Готовые файлы этой рабочей копии

В `bin/ai-studio-bridge` подготовлены ZIP расширения, Gate версии
`1.5.0-ai-studio-alpha.4` и агент версии `1.5.0-ai-studio-alpha.1`.
Расширение имеет собственную версию `0.1.5`.

### Обновление до 0.1.5: связь с открытой вкладкой

При ошибке отсутствующего обработчика (`Receiving end does not exist`) запуск
сеанса сам загружает обработчик в выбранную вкладку AI Studio и повторяет связь.
Для этого добавлено разрешение Chrome `scripting`: выполнение локальных файлов
расширения в разрешённой вкладке AI Studio. Повторная загрузка не создаёт второй
обработчик. Распакуйте новый ZIP поверх прежней папки, сохранив путь, обновите
расширение в chrome://extensions и примите новое разрешение, если Chrome спросит.
Обновите вкладку AI Studio, нажмите «Запустить сеанс» и отправьте новую задачу:
ответы из истории автоматически не выполняются.
Gate alpha.4 и агент alpha.1 обновлять и перезапускать не нужно.
Готовый агент уже скомпилирован: bin/ai-studio-bridge/webcodex-agent.exe;
самостоятельная сборка не нужна.

### Сохранённый вход: обновление до 0.1.4

Обновите и перезапустите Docker Gate до alpha.4 по [инструкции](UPDATE_DOCKER.ru.md).
Распакуйте свежий ZIP поверх прежней папки расширения, сохранив путь. Нажмите
«Обновить» у AI Studio Bridge в chrome://extensions и перезагрузите AI Studio.
Один раз подключитесь заново: старые токены имели суточный срок действия.
Новый токен Bridge сохраняется локально в профиле Chrome и практически бессрочен.
Расширение восстанавливает подключение после перезапуска Chrome. Обновление
страницы AI Studio требует нового сеанса чата, но не повторного входа в Gate.
Кнопка «Отключить» удаляет сохранённый токен; сохранение настроек Bridge в Gate
отзывает выданные токены. Пароль администратора в расширении не сохраняется.
Удаление расширения или данных профиля также удаляет сохранённый вход.
Агент alpha.1 заменять и перезапускать не нужно: готовый EXE уже скомпилирован
в bin/ai-studio-bridge/webcodex-agent.exe, самостоятельная сборка не требуется.

### Обновление до 0.1.3

Исправлено распознавание кнопки AI Studio с текстом `Run` и значком
`keyboard_return`, которая вызывала `ambiguous generation controls`.
Распакуйте новый ZIP поверх прежней папки, сохранив путь. Нажмите «Обновить»
у AI Studio Bridge в chrome://extensions и перезагрузите вкладку AI Studio.
Gate alpha.3 и агент alpha.1 обновлять или перезапускать для этой правки не нужно.
Готовый агент уже скомпилирован: bin/ai-studio-bridge/webcodex-agent.exe;
самостоятельная сборка не нужна.

| Файл | Назначение |
| --- | --- |
| `webcodex-ai-studio-bridge.zip` | Распакуйте в отдельную постоянную папку и загрузите её в Chrome. JavaScript уже готов, компиляция не нужна. |
| `webcodex-gate.exe` | Готовый Gate для Windows x64. |
| `webcodex-gate-linux-amd64` | Gate для Linux x64; запуск на Linux отдельно не проверен. |
| `webcodex-agent.exe` | Готовый локальный агент для Windows x64 с внедрённой версией сборки. |

Эти артефакты находятся в локальной рабочей копии; бинарники и ZIP не включаются
в Git. Самостоятельная сборка для использования готовых файлов не требуется.
Если у вас только исходники из Git, смотрите отдельную [инструкцию сборки](BUILD.ru.md).
Наличие собранных файлов не означает, что alpha уже установлена на вашем сервере.

Если Gate работает в Docker, используйте [инструкцию обновления контейнера](UPDATE_DOCKER.ru.md).
Устанавливать Go на сервер и запускать `build.sh` для этого не требуется.

## Установка из локальной папки

Gate alpha.2 исправляет вход через окно Chrome: при подключении появляется
форма логина и пароля администратора Gate, затем подтверждение доступа.
Пароль отправляется только Gate и не передаётся расширению. Если уже установлен
комплект alpha.1, обновите и перезапустите только Gate по Docker-инструкции выше;
агент alpha.1 и расширение 0.1.1 заменять или перезапускать не нужно. Повторите
«Подключить» в панели. Ошибка `Authorization page could not be loaded` в alpha.1
может возникать до показа страницы из-за HTTP Basic Auth.

1. Откройте в Chrome `chrome://extensions` и включите «Режим разработчика».
2. Нажмите «Загрузить распакованное» и выберите именно папку `ai-studio-extension` этого репозитория.
3. Откройте AI Studio Playground (`https://aistudio.google.com/`) и нажмите значок расширения, чтобы открыть боковую панель.
4. В панели скопируйте Extension ID и Redirect URI вида `https://<ID>.chromiumapp.org/webcodex`.
5. В админке Gate откройте `/admin/mcp-clients/<mcp-id>/bridge`, где `<mcp-id>` — внутренний ID MCP-регистрации. Внесите точный Extension ID и список разрешённых инструментов, затем сохраните.
6. Используйте OAuth Client ID, показанный Gate для MCP, в поле панели. Он может отличаться от внутреннего `<mcp-id>`.
7. Введите origin Gate (например, `https://gate.example.com`) и нажмите «Подключить». Подтвердите страницу входа Gate.
8. Выберите агента и сначала только инструменты чтения. Установите флажок разрешения передачи результатов и при необходимости автоматической отправки результатов. В пустом редакторе AI Studio нажмите «Запустить сеанс»: расширение вставит инструкцию. Допишите свою задачу и нажмите Run на сайте. Кнопка «Вставить инструкции» повторно заполняет только пустой редактор и сама ничего не отправляет.

Инструменты, меняющие данные или запускающие действия, требуют отдельного одобрения в панели. Начинайте с чтения и проверяйте ожидающий вызов перед одобрением. Расширение устанавливается локально и не требует Chrome Web Store или самостоятельной компиляции.

## Проверка и тестовый прогон

Кнопка «Демо» использует только фиктивного агента и фиксированный пример текста;
она не читает реальные файлы и не проверяет соединение с Gate. Для ручной проверки:

1. На компьютере агента создайте в разрешённой папке файл `bridge-smoke.txt` со строкой `bridge smoke ok`. Запишите его полный путь, например `C:\work\bridge-smoke.txt`: вместо `C:\work` используйте свою разрешённую папку.
2. Подключите панель к Gate, выберите агента и только `read_file`. Разрешите передачу результатов в Google, но выключите автоматическую передачу.
3. Откройте обычный чат AI Studio с пустым полем ввода. Нажмите «Запустить сеанс» в панели: появится инструкция. Допишите: «Прочитай файл по полному пути C:\work\bridge-smoke.txt через read_file и верни его содержимое», подставив свой путь. Нажмите Run в AI Studio.
4. Дождитесь JSON в поле «Результат» панели со строкой `bridge smoke ok`. Чтение выполняется без отдельного одобрения. Нажмите «Передать результат»: в чате должно появиться пользовательское сообщение `webcodex-result`, после которого модель сможет ответить содержимым файла.
5. Сверьте ответ с `bridge smoke ok`, остановите сеанс и удалите созданный тестовый файл.

API-ключ модели не требуется: запрос отправляет открытая страница AI Studio.
Этот сценарий нужно проверить вручную; автоматические тесты не проверяют ваш браузер.

При обновлении папки расширения нажмите «Обновить» на её карточке в `chrome://extensions`, затем перезагрузите вкладку AI Studio. Gate — отдельная часть: его новые изменения требуют обновить и перезапустить Gate. Это расширение отдельно от существующего `browser-extension`.

При установке этого alpha-комплекта обновите и перезапустите Gate, затем замените
локальный агент приложенным EXE и перезапустите его. До обновления Gate сохраните
SQLite и существующие настройки по штатной инструкции проекта. Существующее
расширение WebCodex Local Browser заменять не нужно; новое AI Studio Bridge
загрузите отдельно и обновите вкладку AI Studio. Работающий комплект 1.4.0
при подготовке этих файлов не заменялся.

Агент скомпилирован; его не требуется собирать самостоятельно при использовании
готового комплекта. В исходниках и тестах проверены вывод версии при старте,
обмен версиями при соединении и повторном соединении, а также старый peer без
версии. При установке проверьте фактические сообщения обеих запущенных программ:
старый EXE нельзя считать обновлённым по наличию новых исходников. Новое живое
соединение с вашим сервером здесь не проверялось.

Если доставка результата имеет неопределённый статус, не отправляйте повторно: проверьте AI Studio и Gate. «Пауза» приостанавливает работу сеанса, «Остановить» останавливает его, но не является общим откатом уже выполненных действий.

### Обновление расширения с 0.1.0 на 0.1.1

Обновите только папку AI Studio Bridge или распакуйте новый ZIP поверх прежней
папки. Сохраните расположение папки: при смене Extension ID потребуется заново
указать его в Gate. В `chrome://extensions` нажмите «Обновить» у AI Studio Bridge,
затем перезагрузите вкладку AI Studio и начните новый сеанс моста. Старые запросы
из истории автоматически не запускаются.

Gate и агент версии `1.5.0-ai-studio-alpha.1` для этой правки повторно обновлять и
перезапускать не нужно; изменения относятся к расширению. Готовый EXE агента уже
скомпилирован и находится в `bin/ai-studio-bridge/webcodex-agent.exe`, собственная
сборка не нужна. Если на сервере всё ещё комплект 1.4.0 без bridge endpoint,
сначала установите Gate и агент alpha-комплекта по инструкции выше. Существующее
расширение WebCodex Local Browser не меняется.

После перезагрузки вкладки мост ставит прежний сеанс на паузу: нажмите
«Остановить», затем «Запустить сеанс» для нужного диалога. Если Gate остаётся
подключённым, повторный вход не нужен. При истечении авторизации сначала
остановите сеанс, затем подключитесь к Gate заново и запустите новый сеанс.
Не повторяйте операцию с неизвестным исходом: сначала проверьте её исход в Gate.

## Создать ZIP расширения

Из корня репозитория выполните:

```powershell
./ai-studio-extension/package.ps1
```

Команда запускает упаковщик без параметров: он проверяет нужные исходники и кладёт ZIP в `bin/ai-studio-bridge`. ZIP включает только файлы расширения, без тестов, журналов и секретов. JavaScript расширения не компилируется; Gate и агент/EXE этим скриптом не собираются.

Чтобы сохранить ZIP в другом месте, передайте параметр `-OutputDirectory` с абсолютным или относительным путём к папке назначения:

```powershell
./ai-studio-extension/package.ps1 -OutputDirectory 'D:\releases\bridge'
```

`-OutputDirectory` задаёт только папку вывода; существующая папка используется как есть. Сборка и упаковка Gate/агента выполняются отдельно штатными скриптами корня репозитория.

## Обновление расширения до 0.1.2

Адрес Gate и OAuth Client ID сохраняются при вводе, включая неудачный вход.
Во время авторизации кнопка показывает «Ожидается вход…» и блокирует повторный
запуск. В постоянном хранилище Chrome сохраняются только эти два поля.

Распакуйте ZIP поверх прежней папки, сохранив её путь. Нажмите «Обновить» у
AI Studio Bridge в chrome://extensions и перезагрузите вкладку AI Studio.
Gate alpha.2 и агент alpha.1 для этой правки обновлять или перезапускать не нужно.
Готовый агент уже скомпилирован: bin/ai-studio-bridge/webcodex-agent.exe;
самостоятельная сборка не нужна. После перехода с 0.1.1 введите адрес и ID
один раз: прежняя версия могла их не сохранить. Если Chrome сообщает об активном
входе после обновления, закройте окно входа. Если его нет, полностью закройте
и снова откройте Chrome перед новой попыткой.
