# WebCodex AI Studio Bridge — alpha 0.3.4

Расширение для Chrome передаёт команды из обычного чата AI Studio первому доступному локальному агенту на `127.0.0.1`. Агент выполняет команды и возвращает результаты напрямую; Gate, OAuth, ключи API и регистрация Native Messaging для локального режима не нужны. Текущая живая страница AI Studio не проверялась; DOM-селекторы остаются alpha.

## Обновление расширения до 0.3.4

При выборе сохранённого чата расширение проверяет системные инструкции так же,
как при открытии нового. Если пресет `WebCodex MCP` есть, он выбирается; если
блока WebCodex нет, он добавляется с сохранением пользовательского текста и
черновика запроса. Уже подходящие инструкции не записываются повторно. Если
именованного пресета нет, существующий личный пресет сохраняет своё имя.

Проверка работает при переключении диалогов внутри одной вкладки и при открытии
сохранённого чата в выбранной вкладке того же окна. Она не привязывает сеанс к
URL или ID чата и не выполняет вызовы из загруженной истории. Следующий новый
запрос пользователя обрабатывается обычным образом. Ручная пауза, отсутствие
согласия и незавершённая операция блокируют автоматическую проверку.

Обновите расширение в `chrome://extensions`, сохраните разговор и перезагрузите
вкладку AI Studio. В панели версии расширения и скрипта вкладки должны быть
`0.3.4`. Агент, Gate и батник Jinn менять или перезапускать не нужно. Агент уже
скомпилирован, готовый EXE — `bin/ai-studio-bridge/webcodex-agent.exe`;
самостоятельная сборка не нужна. Переходы и выбор пресета проверены на тестовых
фикстурах; живая вкладка в этой среде недоступна.

## Обновление расширения до 0.3.3

Исправлен запуск сеанса в новом чате: прекращённый после обновления скрипт
вкладки больше не блокирует повторную загрузку; устойчивое исчезновение и
пользовательских, и модельных сообщений распознаётся как очистка диалога даже
без подходящего названия кнопки. Новый пустой чат может восстановиться после
автоматической паузы из-за временно недоступного редактора. Выбранная пустая
вкладка в том же окне может получить сеанс, если у прежнего нет незавершённой
операции. Ручная пауза, отозванное согласие и неопределённые операции по-прежнему
блокируют автоматическое выполнение.

Панель показывает версию, фактически загруженную Chrome, и отдельно версию
скрипта вкладки AI Studio. Если версии отличаются или скрипт не отвечает,
панель предлагает перезагрузить сохранённую вкладку. Номер в файле панели сам
по себе больше не считается подтверждением обновлённого скрипта.

Нажмите «Обновить» у AI Studio Bridge в `chrome://extensions`, затем сохраните
разговор и перезагрузите вкладку AI Studio. Откройте новый пустой чат: расширение
должно записать системные инструкции и перейти в ожидание ответа модели.
Проверки автоматического запуска и повторного подключения выполнены на
фикстурах; текущее состояние живой вкладки из этой среды недоступно.
Агент `1.5.0-ai-studio-alpha.4`, Gate и батник Jinn заменять, обновлять или
перезапускать не нужно. Агент уже скомпилирован, готовый EXE находится в
`bin/ai-studio-bridge/webcodex-agent.exe`; самостоятельная сборка не нужна.

## Обновление расширения до 0.3.2

Исправлено распознавание ответа с пояснением перед одним блоком вызова, когда
AI Studio показывает метку `Webcodex-call` в заголовке блока, но не оставляет её
в атрибуте языка. Например, `read_file` после «I will verify if the file exists»
теперь распознаётся как вызов. Текст мыслей и кнопок блока не учитывается;
обычный JSON-пример и несколько блоков автоматически не выполняются.
Регрессионный случай воспроизведён на DOM-фикстуре по скриншоту пользователя;
чтение текущего DOM живой вкладки при этой проверке не выполнялось.

Обновите только файлы расширения или распакуйте новый ZIP поверх прежней папки,
затем нажмите «Обновить» у AI Studio Bridge в `chrome://extensions`.
Перезагрузите сохранённую вкладку AI Studio и заново отправьте запрос, который
остановился на блоке вызова: старые ответы из истории не запускаются автоматически.
Несохранённый разговор сначала сохраните. Агент `1.5.0-ai-studio-alpha.4` и Gate
заменять, обновлять или перезапускать не нужно; универсальный батник сохраняется.
Агент уже скомпилирован, готовый EXE — `bin/ai-studio-bridge/webcodex-agent.exe`;
самостоятельная сборка не нужна.

## Установка текущей версии

Готовый комплект этой рабочей копии находится в `bin/ai-studio-bridge`: ZIP расширения версии `0.3.4` и скомпилированный агент `webcodex-agent.exe` версии `1.5.0-ai-studio-alpha.4`. Самостоятельно собирать агент не нужно. В Git готовые EXE и ZIP не хранятся; если скачаны только исходники, подготовка комплекта описана отдельно в [BUILD.ru.md](BUILD.ru.md). Gate остаётся `1.5.0-ai-studio-alpha.4` и для локального режима не требуется.

1. Замените папку расширения файлами из `bin/ai-studio-bridge/webcodex-ai-studio-bridge.zip` (либо распакуйте ZIP поверх прежней папки), затем в `chrome://extensions` нажмите «Обновить» у AI Studio Bridge.
2. Если компьютер уже подключён к Gate, сохраните его личный батник и все настройки Gate, токен, корни доступа и параметры браузера. Батник должен запускать новый EXE из `bin/ai-studio-bridge` без `--local`: тогда один агент одновременно доступен локальному расширению и другим MCP-клиентам через Gate. Для отдельного режима только с локальным расширением запустите `start-local-agent.cmd` из корня проекта и оставьте окно открытым. Альтернатива для этого отдельного режима — в PowerShell, открытом в папке проекта, выполните:

   ```powershell
   .\bin\ai-studio-bridge\webcodex-agent.exe --local
   ```

   `--local` включает только локальное соединение и игнорирует сохранённые переменные подключения к Gate. Путь после `.\` указывает на уже скомпилированный EXE относительно текущей папки. Без параметров и без настроек Gate агент тоже работает локально. По умолчанию разрешена текущая папка запуска; если ранее сохранены локальные корни, используются они. Переменная окружения `WEBCODEX_ALLOWED_ROOTS` имеет приоритет над ними: её значение — абсолютные пути разрешённых папок через точку с запятой. Скрипт запуска выбирает папку проекта как текущую.
3. В `chrome://extensions` нажмите «Обновить» у AI Studio Bridge. Расширение само найдёт первый отвечающий агент на локальных портах `47831–47840`. Если агент запущен позже расширения, открытая панель повторит поиск. Перезагрузите вкладку AI Studio с уже сохранённым разговором, чтобы обновились скрипт и системные инструкции. Несохранённую вкладку не перезагружайте.

При обновлении с `0.3.0` замените и перезапустите агент, обновите расширение. Gate обновлять, запускать или перезапускать не нужно. Уже собранный EXE находится в `bin/ai-studio-bridge/webcodex-agent.exe`; самостоятельная сборка не нужна. Агент из корня проекта, собранный до этого обновления, локальный порт не открывает и требует замены для этого режима. Обновлённый агент также открывает локальное соединение при обычном запуске с настройками Gate, прежде чем пытаться связаться с сервером.

Агент принимает запросы только через loopback и только от доверенного расширения. Для распакованного расширения его ID автоматически читается из профилей Chrome; папка расширения должна называться `ai-studio-extension` или `webcodex-ai-studio-bridge` и находиться рядом с EXE либо в папке проекта над `bin/ai-studio-bridge`. ID вручную вводить не нужно, реестр не меняется. Установите расширение до запуска агента; если затем перенесли его в другую папку, перезапустите агент. В журнале при запуске есть версия агента, при каждом подключении — фактические версии агента и расширения.

Ошибка `Specified native messaging host not found` относится к прежнему соединению в `0.3.0`. После обновления до `0.3.1` оно не используется. Проверьте версию в панели, обновите расширение и запустите новый EXE. Повторная регистрация host для исправления не нужна.

Если на компьютере уже есть личный батник `start-agent-<имя>.bat`, используйте
его для обычного запуска готового `bin/ai-studio-bridge/webcodex-agent.exe`
без `--local`: один процесс обслуживает и локальное расширение, и MCP-клиентов
через Gate одновременно. Скрипт `start-local-agent.cmd` предназначен только
для отдельного режима без Gate и для универсального запуска не подходит.
`<имя>` означает имя вашего компьютера в названии уже существующего файла;
переименовывать его не нужно. Личный батник сохраняет свой список разрешённых
папок в `WEBCODEX_ALLOWED_ROOTS`, выбирает папку проекта независимо от места
запуска и оставляет окно открытым после завершения агента, чтобы была видна
ошибка. Сохраните в батнике прежние `WEBCODEX_GATE_URL` (адрес своего Gate),
`WEBCODEX_AGENT_TOKEN` (выданный этому компьютеру токен), список папок и настройки
браузера. Удалять или менять токен для этого обновления не нужно. Личные батники
остаются локальными и в Git не добавляются.

Агент обрабатывает каналы отдельно: в консоли и событиях команд стоят отметки
`source=local` и `source=gate`. У каждого канала свои процессы, результаты,
история и ключи повторных запросов. Локальный ответ возвращается расширению,
ответ на запрос Gate — тому Gate, откуда пришёл запрос. Разрыв соединения Gate
не отключает локальный доступ; сбой локального порта не мешает подключиться
к Gate. Локальный канал предоставляет файловые и командные инструменты;
браузерные настройки универсального агента сохраняются для обращений через Gate.

Для этого обновления используйте готовый EXE из `bin/ai-studio-bridge`,
закройте старые экземпляры агента этого компьютера и запустите его личный батник
заново. Самостоятельная сборка не нужна. Если расширение уже обновлено до
`0.3.1`, обновлять его ещё раз не требуется. Gate обновлять или перезапускать
не нужно; существующие клиенты MCP продолжат подключаться через него.

Агент `1.5.0-ai-studio-alpha.4` уже скомпилирован для разделения каналов. При
переходе с агента `alpha.3` замените EXE и перезапустите только агент через
универсальный батник. Расширение `0.3.1` и Gate остаются прежними; повторно
обновлять или перезапускать их не требуется.

Каждый новый сеанс сначала использует первый доступный локальный агент, затем при необходимости обращается к ранее настроенному резервному Gate-маршруту. Пока активен локальный режим, кнопка «Настроить резерв Gate» задаёт подключение и целевой компьютер для будущих сеансов, но не переключает текущий сеанс. Уже работающий сеанс Gate остаётся на нём до остановки и запуска нового сеанса. Для текущего локального сеанса сохраняются адрес и идентификатор агента: при обрыве связи его операции не отправляются другому агенту или Gate. Старую незавершённую операцию Native Messaging без идентификатора агента нужно проверить вручную перед новым сеансом. Проверяйте выбранные инструменты и подтверждайте операции по настройке согласия, как и раньше. Если исход команды неизвестен, результат автоматически повторно не отправляется, а команда не запускается заново.

Расширение работает в одной активной вкладке и не привязывает сеанс к URL или ID чата. Не используйте эту вкладку одновременно для несвязанного разговора. Ключи AI Studio не нужны: страница AI Studio остаётся обычным интерфейсом модели.

## История прежних выпусков (0.2.x и старше)

Ниже оставлены заметки для старых версий. Инструкции в них относятся только к указанным историческим выпускам.

### Обновление до 0.2.16: безопасное отображение JSON результата

Новое сообщение результата отправляется fenced-блоком `webcodex-result`, чтобы
кавычки и обратные косые черты в JSON сохранялись при отображении AI Studio.
Внутренние конверты расширения остаются обычным JSON. Для результата старого
формата с зависшей доставкой проверяется совпадение всего сохранённого текста
результата и полного текста после Markdown-обработки в DOM. После перезагрузки расширения
сначала проверяется видимый результат; затем для восстановления принимается
текущий следующий вызов модели. При неопределённом исходе результат не
отправляется повторно вслепую, операция не запускается заново. Привязки сеанса
к ID чата или URL нет.

Замените файлы в исходной папке расширения либо распакуйте готовый ZIP поверх
прежней папки. В `chrome://extensions` нажмите «Обновить» у AI Studio Bridge,
затем перезагрузите уже сохранённую вкладку AI Studio. Вкладку с несохранённым
разговором оставьте открытой и не перезагружайте. После перезагрузки вкладки
проверьте состояние сеанса в панели. Gate `1.5.0-ai-studio-alpha.4` и агент
`1.5.0-ai-studio-alpha.1` заменять, обновлять или перезапускать не нужно.
Агент скомпилирован; готовый EXE находится в
`bin/ai-studio-bridge/webcodex-agent.exe`, самостоятельная сборка не нужна.
Регрессионный случай составлен по выводу диагностики пользовательской страницы;
исправление в живой AI Studio отдельно не проверялось.

### Обновление до 0.2.15: подтверждение передачи и продолжение хода

После передачи результата расширение проверяет наличие в открытой вкладке
AI Studio точного видимого `webcodex-result` с тем же `operation_id`. Если статус
передачи неизвестен, результат вслепую не отправляется повторно. Предыдущее
подтверждение доставки не засчитывается как новый ход модели, поэтому быстрый
последующий ответ не теряется. Сеанс по-прежнему работает в одной активной
вкладке без привязки к ID чата или URL.

Замените файлы исходной папки расширения, нажмите «Обновить» у него в
`chrome://extensions`, затем перезагрузите уже сохранённую вкладку AI Studio.
Вкладку с несохранённым разговором оставьте открытой и не перезагружайте.
Если статус операции неопределён, проверьте панель и видимый результат; не
запускайте команду заново. Gate `1.5.0-ai-studio-alpha.4` и агент
`1.5.0-ai-studio-alpha.1` заменять, обновлять или перезапускать не нужно.
Агент уже скомпилирован; готовый EXE —
`bin/ai-studio-bridge/webcodex-agent.exe`; самостоятельная сборка не нужна.
Живая проверка AI Studio не выполнялась.

### Обновление до 0.2.14: одна активная вкладка без привязки к чату

Сеанс расширения действует в одной активной вкладке AI Studio и не привязывается
к ID чата или URL. Изменение пути, включая переход из `/prompts/new_chat` в URL
сохранённого prompt, не останавливает сеанс. Внутренние ключи операций остаются
для защиты от повторного выполнения команды.

Переключение на другой чат в той же вкладке не изолируется по URL. Перед началом
несвязанного разговора завершите или остановите текущую команду. Не запускайте
один сеанс расширения в нескольких вкладках. При обновлении расширения нажмите
«Обновить» на его карточке в `chrome://extensions`, затем перезагрузите нужную
вкладку AI Studio, чтобы обновились скрипты. Сначала сохраните разговор, если в
нём есть несохранённые изменения. Перезагрузка может приостановить сеанс;
проверьте его состояние в панели перед продолжением. Gate `1.5.0-ai-studio-alpha.4` и
agent `1.5.0-ai-studio-alpha.1` заменять, обновлять или перезапускать не нужно.
Агент скомпилирован; готовый EXE находится в
`bin/ai-studio-bridge/webcodex-agent.exe`, самостоятельная сборка не нужна.

В инструкциях сеанса указано сначала вызвать `list_allowed_roots`, прежде чем
вызывать `exec_command`. Используйте только выданные Gate разрешённые корни и не
предполагайте ОС или путь. `Active turn` и ID в запросе указывать не нужно.

Если Chrome загружает расширение из исходной папки
`C:\projects\webcdx\ai-studio-extension`, обновите файлы в этой папке; затем
откройте `chrome://extensions` и нажмите «Обновить» у AI Studio Bridge. После
этого перезагрузите вкладку уже сохранённого чата, чтобы обновились скрипт и
системные инструкции. Не перезагружайте вкладку с несохранённым разговором.
Ожидающий результат проверяется по записи операции и наличию его сообщения в
выбранной вкладке, без проверки URL. Команда заново не запускается.
Живая проверка интерфейса AI Studio не выполнялась.

### Обновление до 0.2.12: адреса сохранённых чатов

У AI Studio у сохранённых чатов разные адреса. Переход из `/prompts/new_chat`
на адрес первого сохранённого prompt считается тем же чатом, пока нет ожидающей
операции Gate. Другой адрес сохранённого чата считается сменой чата и остаётся
защищённым: расширение не переносит туда сеанс, ожидающую операцию или результат.
Вызов инструмента можно сопровождать коротким пояснением перед одним fenced
блоком `webcodex-call`. Вставлять `Active turn` в поле ввода не нужно.

Если Chrome использует исходную папку `C:\projects\webcdx\ai-studio-extension`,
обновите её файлы напрямую; затем откройте `chrome://extensions` и нажмите
«Обновить» у AI Studio Bridge. Если текущий разговор уже сохранён и имеет адрес
вида `/prompts/<идентификатор>`, перезагрузите эту вкладку: расширение заново

## Установка из локальной папки

Gate alpha.2 исправляет вход через окно Chrome: при подключении появляется
форма логина и пароля администратора Gate, затем подтверждение доступа.
Пароль отправляется только Gate и не передаётся расширению. Если уже установлен
комплект alpha.1, обновите и перезапустите только Gate по Docker-инструкции выше;
агент alpha.1 и расширение 0.1.1 заменять или перезапускать не нужно. Повторите
«Подключить» в панели. Ошибка `Authorization page could not be loaded` в alpha.1
может возникать до показа страницы из-за HTTP Basic Auth.

1. Откройте в Chrome `chrome://extensions` и включите «Режим разработчика».
2. Нажмите «Загрузить распакованное» и выберите именно папку `ai-studio-extension` этого репозитория.
3. Откройте AI Studio Playground (`https://aistudio.google.com/`) и нажмите значок расширения, чтобы открыть боковую панель.
4. В панели скопируйте Extension ID и Redirect URI вида `https://<ID>.chromiumapp.org/webcodex`.
5. В админке Gate откройте `/admin/mcp-clients/<mcp-id>/bridge`, где `<mcp-id>` — внутренний ID MCP-регистрации. Внесите точный Extension ID и список разрешённых инструментов, затем сохраните.
6. Используйте OAuth Client ID, показанный Gate для MCP, в поле панели. Он может отличаться от внутреннего `<mcp-id>`.
7. Введите origin Gate (например, `https://gate.example.com`) и нажмите «Подключить». Подтвердите страницу входа Gate.
8. Выберите агента и сначала только инструменты чтения. Установите флажок разрешения передачи результатов и при необходимости автоматической отправки результатов. В пустом редакторе AI Studio нажмите «Запустить сеанс»: расширение сохранит правила и схемы выбранных инструментов в отмеченном блоке System instructions, а поле чата оставит пустым. Напишите задачу и нажмите Run на сайте; идентификатор хода не требуется. Если редактор System instructions недоступен, расширение покажет ошибку и не вставит длинную инструкцию в чат. Кнопка «Обновить инструкции» записывает системный блок, не меняет текст задачи и ничего не отправляет.

Инструменты, меняющие данные или запускающие действия, требуют отдельного одобрения в панели. Начинайте с чтения и проверяйте ожидающий вызов перед одобрением. Расширение устанавливается локально и не требует Chrome Web Store или самостоятельной компиляции.

## Проверка и тестовый прогон

Кнопка «Демо» использует только фиктивного агента и фиксированный пример текста;
она не читает реальные файлы и не проверяет соединение с Gate. Для ручной проверки:

1. На компьютере агента создайте в разрешённой папке файл `bridge-smoke.txt` со строкой `bridge smoke ok`. Запишите его полный путь, например `C:\work\bridge-smoke.txt`: вместо `C:\work` используйте свою разрешённую папку.
2. Подключите панель к Gate, выберите агента и только `read_file`. Разрешите передачу результатов в Google, но выключите автоматическую передачу.
3. Откройте обычный чат AI Studio с пустым полем ввода. Нажмите «Запустить сеанс» в панели: правила сохранятся в System instructions, поле чата останется пустым. Напишите: «Прочитай файл по полному пути C:\work\bridge-smoke.txt через read_file и верни его содержимое», подставив свой путь. Нажмите Run в AI Studio.
4. Дождитесь JSON в поле «Результат» панели со строкой `bridge smoke ok`. Чтение выполняется без отдельного одобрения. Нажмите «Передать результат»: в чате должно появиться пользовательское сообщение `webcodex-result`, после которого модель сможет ответить содержимым файла.
5. Сверьте ответ с `bridge smoke ok`, остановите сеанс и удалите созданный тестовый файл.

API-ключ модели не требуется: запрос отправляет открытая страница AI Studio.
Этот сценарий нужно проверить вручную; автоматические тесты не проверяют ваш браузер.

При обновлении папки расширения нажмите «Обновить» на её карточке в `chrome://extensions`, затем перезагрузите вкладку AI Studio. Gate — отдельная часть: его новые изменения требуют обновить и перезапустить Gate. Это расширение отдельно от существующего `browser-extension`.

При установке этого alpha-комплекта обновите и перезапустите Gate, затем замените
локальный агент приложенным EXE и перезапустите его. До обновления Gate сохраните
SQLite и существующие настройки по штатной инструкции проекта. Существующее
расширение WebCodex Local Browser заменять не нужно; новое AI Studio Bridge
загрузите отдельно и обновите вкладку AI Studio. Работающий комплект 1.4.0
при подготовке этих файлов не заменялся.

Агент скомпилирован; его не требуется собирать самостоятельно при использовании
готового комплекта. В исходниках и тестах проверены вывод версии при старте,
обмен версиями при соединении и повторном соединении, а также старый peer без
версии. При установке проверьте фактические сообщения обеих запущенных программ:
старый EXE нельзя считать обновлённым по наличию новых исходников. Новое живое
соединение с вашим сервером здесь не проверялось.

Если доставка результата имеет неопределённый статус, не отправляйте повторно: проверьте AI Studio и Gate. «Пауза» приостанавливает работу сеанса, «Остановить» останавливает его, но не является общим откатом уже выполненных действий.

## Создать ZIP расширения

Из корня репозитория выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./ai-studio-extension/package.ps1
```

`powershell` запускает отдельный PowerShell. `-NoProfile` отключает загрузку пользовательского профиля, `-ExecutionPolicy Bypass` разрешает скрипт только в этом процессе без изменения системной политики. `-File` указывает путь упаковщика относительно корня проекта. Без дополнительных параметров упаковщик проверяет исходники и кладёт ZIP в `bin/ai-studio-bridge`. ZIP включает только файлы расширения, без тестов, журналов и секретов. JavaScript расширения не компилируется; Gate и агент/EXE этим скриптом не собираются.

Чтобы сохранить ZIP в другом месте, передайте параметр `-OutputDirectory` с абсолютным или относительным путём к папке назначения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./ai-studio-extension/package.ps1 -OutputDirectory 'D:\releases\bridge'
```

Параметры PowerShell имеют тот же смысл, что в предыдущей команде. `-OutputDirectory` задаёт только папку вывода; замените `D:\releases\bridge` на нужный путь. Существующая папка используется как есть. Сборка и упаковка Gate/агента выполняются отдельно по инструкции сборки.
