# Правила работы с репозиторием

После каждого завершённого этапа работы:

1. Выполнить необходимые проверки изменений.
2. Создать коммит с понятным, самообъясняющим сообщением: что изменилось и зачем.
   В конце заголовка в круглых скобках указать, к какой части проекта относится
   коммит. Например: `Preserve database during server updates (deployment docs)`.
3. Сразу отправить коммит в соответствующую ветку удалённого репозитория через
   `git push`. Не откладывать push до завершения всей задачи и не запрашивать
   повторное подтверждение: пользователь разрешил это для каждого завершённого этапа.
4. Сообщить пользователю результат. При ошибке push устранить причину в рамках
   задачи или явно сообщить, что коммит пока не отправлен.

В коммиты включать только изменения завершённого этапа. Не добавлять токены,
пароли, локальные настройки, журналы, резервные копии и собранные бинарники.
Не использовать force push без отдельного явного разрешения пользователя.

## Инструкции для пользователя

Писать инструкции простым языком. Рядом с каждой командой объяснять её назначение,
каждый параметр/флаг, аргумент, переменную окружения и заполнитель пути:
что означает, что меняет и какое значение пользователю подставить.
При изменении команды сразу обновлять пояснения в том же документе.
В каждой инструкции обновления явно указывать, нужно ли заменять агент,
обновлять Gate и расширение, а также что требуется перезапустить.
Явно указывать, скомпилирован ли агент, где взять готовый EXE и нужна ли пользователю
самостоятельная сборка. Не смешивать установку готового комплекта со сборкой из исходников.

## Обязательное требование к следующему обновлению

До выпуска следующего обновления реализовать вывод текущей версии агента при его
старте и текущей версии Gate при старте Gate. После успешного соединения и каждого
повторного подключения выводить в консоли агента и журнале Gate версии обеих сторон.
Версию удалённой стороны получать при соединении, не подставлять локальную версию.
Если старая сторона не передаёт версию, явно писать «версия не передана».
Требование пользователя от 2026-10-25 отложено до следующего обновления:
само его внесение в план не требует менять код или пересобирать текущий комплект 1.4.0.
