# WebCodex: локальный MCP для файлов и команд

WebCodex публикует явные операции с файлами и процессами локальных Windows/Linux-компьютеров через единый MCP Gate. Gate сохраняет OAuth, SQLite, маршрутизацию по агентам и политику инструментов; локальный agent устанавливает только исходящее соединение.

English: [README.md](README.md) · Пошаговый запуск: [USER_GUIDE.ru.md](USER_GUIDE.ru.md) · [Как обновить сервер](UPDATE_SERVER.ru.md)

```text
MCP-клиент ── HTTPS + OAuth ──> Gate ── исходящий NDJSON ──> Local agent
                                │                            │
                                └─ SQLite, policy            └─ файлы, процессы, логи
```

## Контракт инструментов

`/mcp/v4` публикует одиннадцать файловых и командных операций и `list_allowed_roots`. `/mcp/v3` сохраняет семь прежних операций и также добавляет сведения о каталогах. Gate предоставляет `list_agents`.

`/mcp/v5` добавляет `list_commands` и `request_key` для устойчивого Retry.
При локальном `WEBCODEX_BROWSER_ENABLED=1` доступны ещё десять инструментов
для clean/persistent/personal-браузера. [Настройка браузера](BROWSER_GUIDE.ru.md).

Для своего залогиненного Chrome/Edge один раз включите **«Постоянный доступ
ко всем вкладкам сайтов»** в расширении WebCodex Local Browser. Связь после
перезапусков и доступ к вкладкам восстанавливаются автоматически.
Пауза сохраняется; «Отключить всё» выключает постоянный доступ.

| Инструмент | Операция |
| --- | --- |
| `list_agents` | Список доступных компьютеров и состояние подключения (Gate). |
| `list_allowed_roots` | Действующие разрешённые каталоги выбранного компьютера. |
| `read_file` | Чтение UTF-8 файла или диапазона строк. |
| `write_file` | Атомарное создание или замена файла с обязательным предусловием. |
| `list_directory` | Нерекурсивный листинг каталога. |
| `search_files` | Поиск подстроки или регулярного выражения по текстовым файлам. |
| `exec_command` | Запуск shell-команды или argv с env/stdin и раздельными ограниченными логами. |
| `poll_command` | Чтение новых байт stdout/stderr и статуса процесса. |
| `cancel_command` | Завершение дерева процессов. |
| `edit_file` | Точные замены с проверкой SHA-256 полного файла. |
| `find_files` | Рекурсивный поиск файлов и каталогов по glob имени. |
| `move_path` | Переименование обычного файла или пустого каталога без перезаписи. |
| `delete_path` | Удаление файла с проверкой хеша или пустого каталога. |

Пути и рабочий каталог команды должны быть абсолютными. Нет разбора задач на естественном языке, истории диалога, интерактивного терминала и алиасов инструментов.

## Сборка и проверка

Нужен Go 1.25 или новее.

```powershell
go test -count=1 ./...
go vet ./...
go build -o webcodex-agent.exe ./cmd/agent
go build -o bin/webcodex-gate.exe ./cmd/gate
```

Скрипты `build.bat` и `build.sh` собирают оба бинарника.

## Gate

Скопируйте `.env.example` в `.env`, задайте сложный пароль администратора и запустите:

```bash
docker compose up -d --build
```

Текущий endpoint коннектора — `/mcp/v5`; v3/v4 сохранены для отката. Остальные основные endpoint: `/oauth/authorize`, `/oauth/token`, `/agent/stream`, `/agent/result`, `/admin`, и `/healthz`. Gate должен работать за HTTPS. OAuth требует PKCE S256 и известный callback ChatGPT или Gemini (`https://oauth-redirect.googleusercontent.com/r/user_bound_custom-mcp-<id>`). Одинаковые OAuth-данные MCP-подключения можно использовать для обоих клиентов; их access token действуют независимо. Срок access token задаёт `WEBCODEX_ACCESS_TOKEN_TTL`, по умолчанию 24 часа.

В `/admin` агенты и MCP-подключения регистрируются отдельно. При создании агента сохраните его Agent Token; при создании MCP-подключения — OAuth Client ID и Secret. Секреты показываются один раз; в SQLite сохраняются только SHA-256 хеши.

### Несколько компьютеров через один URL MCP

1. В разделе «Агенты» зарегистрируйте каждый компьютер и запустите локальный
   agent с его собственным `WEBCODEX_AGENT_TOKEN` и общим `WEBCODEX_GATE_URL`.
2. В разделе «MCP-подключения» создайте отдельное подключение, сохраните его OAuth
   Client ID и Secret, затем в карточке отметьте разрешённые компьютеры.
3. В Gemini или ChatGPT подключите один URL `https://example.com/mcp/v5` с этими
   OAuth-данными. Токены локальных агентов передавать MCP-клиенту не нужно.

Вызовите `list_agents` для получения ID и online-статуса. В вызовах файловых,
командных и браузерных инструментов передавайте `agent_id`, например
`list_allowed_roots({"agent_id":"home-pc"})` или
`read_file({"agent_id":"home-pc","path":"C:\\projects\\app\\README.md"})`.
Для продолжения командных и браузерных сессий используйте тот же `agent_id`.
При нескольких назначенных агентах выбор обязателен; при единственном его можно
опустить для совместимости с прежними коннекторами. Неизвестный, отключённый или
offline-компьютер не заменяется другим. Политика инструментов применяется к
выбранному агенту.

Права MCP-подключения проверяются при каждом запросе и распространяются на все
его активные OAuth-сессии. Агенты и MCP включаются, удаляются и ротируют секреты
независимо. Удаление агента убирает его из подключений, сохраняя остальные агенты,
OAuth-данные и токены доступа. Отключение MCP закрывает доступ через него, не
останавливая локальные агенты. При обновлении старой базы Gate автоматически
переносит прежние OAuth-данные и access token в отдельные MCP-регистрации,
сохраняя их привязку к прежнему компьютеру.

Список инструментов объединяется из подключённых разрешённых агентов;
`list_agents` работает даже когда все компьютеры offline или список назначений пуст.
После изменения доступа или подключения компьютера обновите инструменты либо
переподключите коннектор. Агентов в группе обновляйте вместе: одинаковые имена
инструментов должны иметь одинаковые схемы входа и выхода.

## Локальный agent

Пример для Windows PowerShell:

```powershell
$env:WEBCODEX_GATE_URL = "https://example.com"
$env:WEBCODEX_AGENT_TOKEN = "<токен из /admin>"
$env:WEBCODEX_ALLOWED_ROOTS = "C:\projects;W:\"
$env:WEBCODEX_BROWSER_ENABLED = "1"
$env:WEBCODEX_LOG_DIR = "$PSScriptRoot\logs"
./webcodex-agent.exe
```

Пример Linux environment file:

```env
WEBCODEX_GATE_URL=https://example.com
WEBCODEX_AGENT_TOKEN=<токен из /admin>
WEBCODEX_ALLOWED_ROOTS=/srv/projects:/opt/work
WEBCODEX_LOG_DIR=/var/log/webcodex-agent
WEBCODEX_PROCESS_TTL=24h
WEBCODEX_MAX_LOG_BYTES=52428800
```

По умолчанию в карточке агента разрешены `C:\projects` и `W:\`. Без локальной `WEBCODEX_ALLOWED_ROOTS` агент загружает каталоги с `/agent/config` при запуске. Значение в локальном .bat, .ps1 или environment полностью перекрывает настройки Gate. После изменения настроек перезапустите агент; скачанный скрипт содержит локальную копию каталогов. Для наследования настроек Gate удалите строку `WEBCODEX_ALLOWED_ROOTS` из скрипта. Недоступные при запуске каталоги не дают доступа; после подключения диска перезапустите агент. `list_allowed_roots` возвращает действующие пути, их доступность и флаг неограниченного доступа. Скачиваемые .bat/.ps1 включают браузинг через `WEBCODEX_BROWSER_ENABLED=1`; локально можно задать `0`. Для Linux задайте его абсолютные пути в админке либо environment. Значение `WEBCODEX_ALLOWED_ROOTS=*` сознательно открывает все пути. Перед проверкой разрешённых корней symlink/reparse path разрешается до фактического пути.

Каждая command-сессия хранится в `<log-dir>/<session-id>/`: `metadata.json`, `stdout.log`, `stderr.log`. В metadata нет текста команды, stdin и значений environment. Завершённые сессии доступны после перезапуска agent и удаляются через 24 часа. Активная сессия восстанавливается только при совпадении сохранённой идентичности PID.

### Наблюдение за выполнением

Терминал агента по умолчанию показывает command/argv, cwd, session ID, PID,
timeout, пути логов и новые stdout/stderr по мере поступления. Вывод печатается
экранированными фрагментами (`\n` обозначает перевод строки); управляющие
символы не исполняются терминалом. Каждые 10 секунд активный процесс получает
строку `RUNNING`, при завершении — `EXIT` со статусом и exit code.
Отдельно показываются ошибки запуска, запросы остановки и достижение лимита
дисковых логов. После лимита вывод продолжает поступать в терминал.

`WEBCODEX_VERBOSE=0` скрывает command/argv и содержимое stdout/stderr, оставляя
события и статусы. Значения env и stdin не логируются автоматически, но сама
команда или запущенная программа могут вывести секреты. Восстановленные после
перезапуска процессы показывают статус и время; их stdout/stderr доступны через
`poll_command`, а exit code после перезапуска может быть неизвестен.

`exec_command` по умолчанию отвечает через 1 секунду (ожидание не больше 3 секунд,
даже если клиент запросил больше); процесс продолжает работать
в фоне. Обрыв запроса не отменяет процесс: продолжайте `poll_command` с прежним
session ID вместо повторного запуска команды. Для длительного расчёта задавайте
`timeout_seconds` по ожидаемому времени (по умолчанию 1200, максимум 86400).

Gate рекомендует клиенту перед запуском сообщать команду и цель, возвращаться
из `exec_command` через 1–3 секунды и опрашивать работающую сессию через
`poll_command` с возвращёнными offsets. Отчёты в чате примерно раз в 10–20 секунд
зависят от выполнения этих инструкций моделью; автоматической отправки сообщений
в завершённый диалог нет. `running` означает продолжающуюся работу, а успешный
вызов инструмента не равен успешному завершению процесса.

План минимального и расширенного вариантов: [EXECUTION_TRANSPARENCY.ru.md](EXECUTION_TRANSPARENCY.ru.md).

## Безопасность и обновление

В карточке агента откройте «Мониторинг команд и журналы»:
`/admin/agents/<id>/commands`. Каждые 2 секунды обновляются сессии, PID,
статус, exit code и время. Доступны поиск по ID/cwd, фильтр статуса,
раздельные stdout/stderr, события, скачивание и остановка.
Применяются admin auth, права конкретного агента и CSRF для остановки.
На экране последние 256 KiB каждого потока; скачивание — до текущего EOF
или 100 MiB. При offline страница повторяет чтение, команды не запускает.

Для восстановления после Retry подключитесь к `/mcp/v5`: `list_commands`
находит недавние сессии, `exec_command` требует уникальный `request_key`.
Повторяйте тот же ключ и аргументы при потере ответа. Другие аргументы
с тем же ключом отклоняются; неизвестный исход запуска после сбоя даёт
`outcome_unknown`, без повторного процесса. Ключ удаляется вместе с сессией
по `WEBCODEX_PROCESS_TTL`: старый запуск после истечения срока не повторять.
Gate и агент обновляются вместе; существующие операции v3/v4 сохранены. После миграции базы не запускайте старый Gate с новой схемой; для отката используйте резервную копию базы до обновления.

`exec_command` — удалённое выполнение команд с правами пользователя локального agent. `WEBCODEX_ALLOWED_ROOTS` защищает только файловые инструменты и не ограничивает shell. Запрещайте `exec_command` и `cancel_command`, если они не нужны. У новых агентов `edit_file`, `move_path` и `delete_path` запрещены до явного включения.

Запускайте agent под отдельной непривилегированной учётной записью. В Windows выдайте ей NTFS-права только на рабочие каталоги и каталог логов. В Linux настройте `ReadWritePaths` в `deploy/webcodex-agent.service`; unit уже включает `NoNewPrivileges`, `PrivateTmp` и `ProtectSystem`. Если сборкам не нужны загрузки, ограничьте исходящую сеть средствами ОС или контейнера.

Перед обновлением сохраните SQLite, бинарники, service-файлы и command-логи.
Сначала разверните Gate, затем замените agent и при необходимости установите
расширение. Создайте новый connector на `/mcp/v5` и начните новый чат:
до tool policy — 12 инструментов без браузера, 22 с браузером.
Для отката выключите браузер, переключитесь на `/mcp/v4` и верните agent binary;
личные/постоянные профили сохраните.
